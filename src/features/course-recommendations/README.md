# お気に入りとコース推薦

お気に入りは `features/favorites/FavoritesProvider.tsx` に集約する。ゲストは `rusutsu:favorites:v1` へ保存し、Googleログイン後はユーザー・スキー場複合主キーの `Favorite` を正本にする。ゲストの保存を重複なしでDBへマージし、アカウントのお気に入りをブラウザ保存へコピーしない。

Google認証は既存Auth.js設定を再利用する。初回の自動追加は15分のHttpOnly操作Cookieと成功したサインインのnonce一致を条件にし、キャンセルでは追加しない。認証JWTの有効期間は従来どおり30日。ログイン履歴だけを独立した365日のHttpOnly Cookieへ保存し、明示ログアウト時に削除する。「あとで」は同じ閲覧タブで通知を繰り返さない。実GoogleアカウントでのOAuth往復は未確認。

## 現在の推薦仕様（version 2）

2026-10-06の仕様変更で、75点の足切りを撤廃した。お気に入りの別スキー場に有効な比較データがあれば、最大3件を返す。低い点数もCの参考候補として表示する。圧雪・非圧雪の反対状態と通常型・蛇行型の違いは、除外から優先順位へ変更した。

優先順位は、圧雪状態が比較可能で同じ形状分類 → 圧雪状態は比較可能だが形状分類が異なる → 反対の圧雪状態で同じ形状分類 → 両方異なる。同じ優先順位の中ではスコアの高い順。同点はスキー場ID・コースキー順で固定する。不一致は画面上に「圧雪・非圧雪の状態が異なる」「曲がり方が異なる」と明示する。

名前なし・不十分な標高データ・非メインルート・自分のスキー場・共有データのエリア・同一形状の重複は引き続き対象外。有効な元データやお気に入りがない場合に架空の候補は作らない。検索元・候補のデータ不足、別スキー場のお気に入りなしを区別して表示する。

## 特徴量

- `groupKind: routes` は `routeKey` の末尾番号を数値で比較し、最小番号のメインルートだけを採用する。検索元の非メインルートをメインへ置き換えない。
- 連続区間を `sectionOrder` または上部・中部・下部の名称順で接続する。順序不明・重複、水平15m超または標高差5m超の接続は除外する。
- 元の名称・内部名称・グループ表示名を確認し、空、名前不明、名称不明、無名および無名の内部識別名を除外する。
- 全座標・全標高が有限値であることを要求する。欠損を0°へ置き換えない。正規化で失われた不正座標もフラグで保持する。100mを超える疎な線分と40m未満の線は除外する。
- 10mの水平距離で再サンプルし、既存 `calculateCoordinateSlopes` の前後2点（約40m）で斜度を平滑化。滑走距離は水平距離と標高差から求める斜面距離。公式距離を混ぜない。
- 全体の斜度分布は3°の16区分。登り返しは0〜3°、45°以上は最後。滑走距離で加重し合計を1にする。
- **急斜面の斜度 `steepSlope`** は、連続する50mの滑走距離内の平滑化斜度を距離加重平均し、その最大値を採用する。50m未満なら全長。全線分境界と境界から50m手前を評価し、線分途中の窓や始点・終点も取りこぼさない。1点だけの生の最大斜度や公式最大斜度とは異なる指標で、画面に「50m平均」と明示する。
- **急な区間の総距離 `steepDistance`** は、平滑化斜度が `steepSlope` の80%以上である区間の滑走距離を合計する。全線が平坦なら0。長い緩斜面が追加されても、同じ急斜面の特徴が割合で薄まらない。
- 圧雪○・×の混在または△はpartial、未取得区間があればunknown。partial/unknownは圧雪による不一致扱いにしない。
- カーブは前後50mの進行方向から45°以上を検出し、75m以内を集約。3回以上かつ2回/km以上でwinding。カーブをスコアに加算せず、候補の優先順位と不一致表示に使う。

## 地形の近さとA・B・C

各差を0〜1へ正規化し、次の式で0〜100点を計算する。

```text
急斜面の斜度差 DP = min(1, abs(PA - PB) / 12°)
急な区間の距離差 DE = min(1, abs(log((EA + 50m) / (EB + 50m))) / log(3))
全体の斜度分布差 DS = min(1, Wasserstein(histA, histB) / 18°)
全長の差 DL = min(1, abs(log(LA / LB)) / log(3))
S = 100 * [0.50*(1-DP) + 0.25*(1-DE) + 0.15*(1-DS) + 0.10*(1-DL)]
```

急な区間の距離に50mを加えるのは、0mでも対数を計算できるようにし、ごく短い区間の距離比で過度に減点しないため。Wassersteinは累積分布差を3°で15区間だけ積分し、最後の45°以上の無限幅を加算しない。完全一致なら100点、比較方向を逆にしても点数は同じ。

Aは80点以上、Bは60点以上80点未満、Cは60点未満。境界付近で表示点数と評価が矛盾しないよう、点数は小数1桁で切り捨てる。A〜Cは選択コースとの地形の近さで、初心者・上級者の難易度区分ではない。

重み・正規化幅・評価境界は暫定的な設計値で、実測データから再現可能な比較スコアを作るためのもの。スキーヤーの体感一致率として校正した数値ではないので「何%似ている」とは表示しない。定数は `algorithm.ts` の `RECOMMENDATION` に集約。重み・差の正規化・評価境界だけの変更には特徴量の再計算は不要。抽出や平滑化、50m区間の定義、形状分類を変更する場合はversionを上げて再計算する。

## DB・反映

`favorites` と `course_recommendation_features` を使用する。後者は正本GeoJSONのコースID・グループIDを保持する。version 2のマイグレーションは `steepSlope`・`steepDistance` 列を追加する。既存version 1の欠損列はnullのまま保持し、0°として扱わない。検索時はversion 2で新しい特徴量が揃った行だけを使う。

```sh
pnpm prisma migrate deploy
mise run recommendations:rebuild          # dry-run
mise run recommendations:rebuild -- --apply
# 一つだけ再作成する場合
mise run recommendations:rebuild -- --apply --resort=shiga-kogen-central
```

再計算は `DATA_API_BASE_URL` に関係なく `DATABASE_URL` のDBへ行う。本番は正本DB側で実行する必要がある。デプロイ処理はDBバックアップ／マイグレーション後、アプリ起動前に再計算する。失敗時は起動・成功記録へ進まない。DockerはCLIの依存ファイルをコピーし、イメージ作成時に読み込みを確認する。

以後、正本文書の更新・統合・コースID移行と同じトランザクションで再計算する。検索時はお気に入りだけを対象に事前計算済みの行を読み、全GeoJSONを読み直さない。クライアントと本番APIでversionが異なる場合は更新が必要と表示し、待っても表示されないことを明示する。旧スコアを新しい評価として表示しない。

## 表示速度と通信量

標高からの斜度・分布・急斜面・形状の抽出は文書更新／デプロイ時にDBへ事前保存する。閲覧時に残る処理は、お気に入りの特徴量の読み取りと軽いスコア比較だけ。全スキー場の組合せ順位を保存する方式ではなく、その人のお気に入りに合わせて順位を決める。

詳細データが画面へ渡った後、ブラウザの空き時間に `/rusutsu/api/course-recommendations` へ独立したPOSTを送る。詳細・地図はこの応答を待たない。Server Actionの待ち行列へ先読みを追加しない。比較画面でも取得済みの最大4スキー場だけを対象にする。検索元の全メインコースについて各3件までの推薦結果を返すが、座標・標高列・斜度分布は送らない。

結果はアカウント・お気に入り集合別のメモリキャッシュ（最大20スキー場、60秒）へ置き、同時リクエストを共有する。先読み済みならコース選択時に通信しない。選択が先読みより早ければ同じ通信を共有する。ネットワークは3秒で打ち切り、エラーと再試行を表示する。バックエンドAPIにも2.5秒の制限を付ける。失敗は通常画面の表示に影響させない。

2026-10-06、実データの志賀高原中央エリア46コースとルスツ・キロロのお気に入りで測定。全推薦結果のJSONは95,308 bytes（約95KB）、gzip換算13,165 bytes、Brotli換算9,581 bytes。圧縮サイズはローカルで計算した参考値で、実配信で使われる圧縮方式に依存する。

同じ実データを専用ローカルPostgreSQLへ入れた測定では、全46コースのDB取得＋順位計算の中央値3.2ms、p95 4.2ms（10回）。本番の通信時間を含む値ではない。ローカルChromiumで先読み応答を止めても詳細・コースボタンが表示されることを確認し、応答解放後のコース選択では追加通信0件、クリックから推薦DOMまで約30ms、次の描画フレームまで約34msだった。

## 検証

`mise run test`、`mise run check`、Webpack本番ビルドを使用する。DB統合テストは `FAVORITES_TEST_DATABASE_URL` がある場合だけ専用ローカルDB `rusutsu_favorites_test_<数字>` で実行する。通常実行ではDBが必要な2件をスキップする。

急斜面に長い平坦区間を追加する場合、1mのスパイク、区間分割・向き変更、50m未満、全線平坦、急斜面優先の順位、低いスコア・圧雪／形状違いでも候補を返すこと、A/B/C境界を確認する。既存のメインルート・欠損・自己推薦除外・安定した同点順位を維持する。DBでは特徴量の作成・更新・ID移行・nullの除外、APIのゲスト／ログイン別お気に入りとアカウント分離、旧APIのversion不一致を確認する。キャッシュでは同時取得の共有・期限・エラー後再試行・非メインルートを確認する。
