# article.json の箇条書き仕様

## 目的

初めて行く人が、カテゴリごとに「何が滑れるか」「何が計画を制約するか」を短時間で
判断できるようにする。

箇条書きは文章の装飾ではない。**同じ論理カテゴリに属する独立項目の集合**として
設計する。

## 並列性

同じ配列の全項目は、次の問いに答える。

> このスキー場を、この目的で選ぶ判断を変える事実は何か。

各項目は `{ "label": "good|bad|description", "text": "..." }` の辞書にする。全項目を次の点で
そろえる。

- 論理カテゴリ: すべて来場判断に効く事実
- 構造: すべて `label` と `text` の2キー
- 分類: `label` は来場判断への作用を表す
- 文法: `text` は独立した敬体の文
- 時制: 現在の恒常的な特徴を現在形で書く
- 句読点: すべて句点で終える

並列とは、同じ語で書き始めることではない。同じ種類の情報を同じ文型で提示すること。

## 独立性

各項目は単独で意味が通り、順序を入れ替えても壊れないようにする。

### 悪い例

```json
[
  {
    "label": "description",
    "text": "高難度斜面の多くはコブや不整地です。"
  },
  {
    "label": "bad",
    "text": "そのため、選べる圧雪斜面は限られます。"
  }
]
```

2項目目が1項目目に依存している。結論も事実から読者が判断できる。

### 良い例

```json
[
  {
    "label": "good",
    "text": "圧雪急斜面でロングターンを反復できます。"
  },
  {
    "label": "description",
    "text": "高難度斜面の多くはコブか非圧雪です。"
  },
  {
    "label": "bad",
    "text": "一部の上級指定斜面は圧雪頻度がはっきりしません。"
  }
]
```

各項目を単独で表示できる。前項を受ける接続詞もない。

## 1項目1論点

`text` は1文、12〜45字を目安にする。原因と結果を分離すると後項が前項へ依存する
場合だけ、同じ辞書に収める。

```json
[
  {
    "label": "bad",
    "text": "降雪後は競争が早く、午後には新雪が荒れる場合があります。"
  }
]
```

この文の論点は「新雪を狙える時間の制約」で一つ。

1項目に複数の設備、斜面、利用者層を詰め込まない。

## label

`label` は次の順で決める。

1. その事実だけを見て、目的地として選びやすくなるなら `good`。
2. 選びにくくなる、または計画上の負担が増えるなら `bad`。
3. 必要な情報だが、選ぶ判断を直接上げ下げしないなら `description`。

| label | 対象 | 例 |
| --- | --- | --- |
| `good` | 滑れるもの、反復しやすさ、利便性 | 圧雪中斜面でロングターンを反復できる |
| `bad` | 不在、不足、閉鎖、混雑、競争、申請の手間 | 公式ツリーランがない |
| `description` | 地形の性格、雪による変動、評価を伴わない営業条件 | 自然コブは積雪で形が変わる |

肯定文を必ず `good`、否定文を必ず `bad` にはしない。たとえば「急斜面があります」は、
対象カテゴリによって `good` にも `bad` にもなる。事実の内容ではなく、そのカテゴリの
目的に対する作用で分類する。利点や欠点が明確な事実を `description` に入れて評価を
ぼかさない。申請、利用時間の制限、閉鎖可能性は負担を増やすため `bad`。積雪によって
コブの形やアイテム構成が変わることは、変化の方向を決められないため `description`。

## 必要性の判定

各候補について次の順に判定する。

1. `detail.json` に根拠があるか。
2. このカテゴリを目的に行くかどうかが変わるか。
3. ほかの項目や `courses` に同じ事実がないか。
4. 名前を付けられる具体物または具体的な条件があるか。

一つでも満たさなければ削る。字数や項目数を満たすための文は足さない。

### 削る例

- 「初心者やレンタル利用者、家族での滑走に使われています。」
  - 斜面で何ができるかを増やさず、利用者属性を足しただけ。
- 「複数のエリアに、圧雪中斜面、急斜面、自然コブが分かれています。」
  - 設備の棚卸しであり、どれが来場判断を変える強みか分からない。
- 「コース量が支持されています。」
  - 評判の話であり、斜面の事実ではない。

## 語彙

スキーヤーが通常使う具体的な語を選ぶ。調査記録の名詞へ `部`、`場所`、`箇所`を
機械的に足さない。

| 避ける | 根拠に合わせた候補 |
| --- | --- |
| 非圧雪部 | 非圧雪斜面、非圧雪コース、オフピステゾーン |
| 小斜面 | 練習斜面、緩斜面 |
| コブ発生箇所 | コブ斜面、自然コブ |
| 初心者向け場所 | 初心者エリア、練習斜面 |

公式名称があるものは公式名称を使う。ただしコース名は `courses` だけに書く。

## full

`label` / `text` の辞書配列。3〜5項目。

7カテゴリの要約ではない。全体の来場判断を最も大きく変える事実だけを選ぶ。

- 最も強い滑走体験を1〜2項目
- 旅行計画を変える制約を1〜2項目
- 必要な場合だけ、対象の不在や条件付き営業を1項目

エリア数、設備数、斜面タイプを一文で棚卸ししない。「誰に向くか」はscoreと事実から
分かるため、原則として書かない。

## reason

`label` / `text` の辞書配列。2〜5項目。1項目目にはカテゴリで最も目立つ事実を置くが、後続項目を
参照させない。

score別の情報構成は次のとおり。

| score | 必須内容 |
| --- | --- |
| `◎` | 目的にできる具体的な滑走体験。条件や制約があれば追加 |
| `○` | できることと、範囲・量・条件の制約 |
| `△` | 対象がない、または目的にするには構造的に足りない事実 |

`warn: true` で判断材料の少なさが来場判断に影響するときだけ、不確かさを1項目にする。
調査手順、媒体、件数は書かない。

## courses

`{ "name": "コース名", "description": "説明" }` の配列。
`detail.json` にあるコースだけを使い、選び直さない。

`description` は15〜70字。1文40字以内。コース固有の滑走体験と条件を書く。
全長、斜度、標高などの数値は書かない。

## 表現規則

- 敬体で統一する。
- `label` は `good` / `bad` / `description` のいずれかにする。
- `text` を句点で終える。
- 主語と述語を近づける。
- 名前のある具体物を主語にする。
- `そのため`、`したがって`、`一方`、`ただし`、`また`、`さらに`、`なお`で
  項目を始めない。
- `これ`、`それ`、`前者`、`後者`で前項を参照しない。
- `評価`、`声`、`記録`、`実績`、`人気`を記事の根拠として書かない。
- 同じ配列内で同じ事実を言い換えない。
- 数値、URL、引用、媒体名、調査年を本文に出さない。
