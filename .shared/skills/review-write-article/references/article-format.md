# article.jsonの文章と箇条書き

## 目的

初めて行く人が、ゲレンデの様子を短時間で理解し、行き先を比べられるようにする。

記事は調査報告の要約ではない。採点の考え方や分類を説明せず、読み手が現地で見るもの、移動、
混雑、営業条件を直接書く。

## 分かりやすい文の条件

各文は次の条件を満たす。

- 一文で一つのことだけを伝える。
- 斜面、コース、リフト、雪、コブ、パークなどを主語にする。
- 主語と述語を近づける。
- 修飾語を重ねない。何にかかるか分からない文は二つに分ける。
- 読み手が日常的に使う動詞で終える。
- 抽象的な名詞にまとめず、何がどうなるかを書く。
- 前の項目を読まなくても意味が通る。
- 同行者へ口頭で説明しても不自然でない。

### 文全体を書き直す

分かりにくい文を、単語の置換だけで直してはいけない。`detail.json` の事実へ戻り、主語と述語を
選び直す。

| 分かりにくい文 | 問題 | 書き直し例 |
| --- | --- | --- |
| 圧雪急斜面の主力は一系統です。 | 分類語を重ねている | 圧雪された急斜面は一つだけです。 |
| 初級斜面から山頂迂回へ段階的に進めます。 | 何をするのか見えない | 山頂から下る初級者は迂回コースを通ります。 |
| 混雑時の代替周回があります。 | 場所も行動も分からない | 混んだら隣のリフトへ移れます。 |
| コブの物量があります。 | 斜面の様子を想像できない | コブは斜面の上から下まで続きます。 |
| 中級斜面でカービングを反復できます。 | カテゴリの用途を述べただけ | 圧雪中斜面は一つだけで、午後は荒れやすいです。 |

書き直し例は定型文ではない。実際の記事では `detail.json` にある事実だけを使う。

## 読み手が知りたいこと

| カテゴリ | 優先する事実 |
| --- | --- |
| `beginner` | 麓だけか山頂からも下れるか。狭い所、平らな所、混雑はあるか |
| `intermediate` | 圧雪中斜面はいくつあるか。長いか。別の場所への移動は必要か |
| `advanced` | 圧雪急斜面はいくつあるか。ほかの上級斜面はコブや非圧雪か |
| `moguls` | コブはいつもあるか。どこまで続くか。何本あるか |
| `powder` | 非圧雪斜面はいくつあるか。朝の競争、午後の残雪、開放条件はどうか |
| `tree-run` | 公式区域か。申請や受付が必要か。閉鎖条件と出口はどうか |
| `park` | 何があるか。難度別に分かれるか。いつ開くか |

「カービングできる」「高速ターンできる」「パウダーを楽しめる」は掲載しない。同じカテゴリの
多くのスキー場に当てはまり、行き先を決める材料にならない。

## 箇条書き

`full` と `reason` は次の辞書を要素に持つ配列にする。

```json
{
  "label": "bad",
  "text": "圧雪された急斜面は一つだけです。"
}
```

各項目は単独で意味が通る敬体の一文にする。`そのため`、`一方`、`ただし`、`また`、`さらに`、
`なお`で始めない。`これ`、`それ`、`前者`、`後者`で前の項目を参照しない。

### label

| label | 使う場面 |
| --- | --- |
| `good` | 行き先として選びやすくなる事実 |
| `bad` | 行き先として選びにくくなる事実、手間、制限 |
| `description` | 良し悪しを決めない地形や営業条件 |

文章が肯定形か否定形かではなく、来場判断への影響で決める。申請、受付、営業時間の短さ、閉鎖は
`bad`。積雪によってコブの形が変わるだけなら `description`。

### text

- 12〜45字を目安にする。
- 一文だけを書き、句点で終える。
- 箇条書き記号を入れない。
- 数値、年号、媒体名、URL、引用文を入れない。
- コース名を入れない。コース名は `courses` だけで使う。
- 「評価」「支持」「人気」などを根拠として書かない。
- 調査や記事編集の手順を書かない。

字数に収めるために名詞を重ねてはいけない。長い場合は、落としてよい情報を削る。二つの事実が
入っている場合は、独立した二項目に分ける。

## full

`label` / `text` の辞書配列。3〜5項目。

全カテゴリの要約ではない。全体の来場判断を最も大きく変える事実だけを書く。

- 長さ、コース数、範囲など、最も目立つ特徴
- 移動、混雑、申請、営業時間など、旅行計画を変える制約
- 必要な場合だけ、設備や対象斜面がないこと

## reason

`label` / `text` の辞書配列。2〜5項目。

| score | 書く内容 |
| --- | --- |
| `◎` | コース数、長さ、営業の安定など、ほかと比べて目立つ事実 |
| `○` | できることと、コース数の少なさや条件による制約 |
| `△` | 対象がない、または目的にするには足りない事実 |

`warn: true` で不確かさが来場判断に影響するときだけ、分からない内容を一項目にする。調査件数や
媒体は書かない。

## courses

`{ "name": "コース名", "description": "説明" }` の配列。

`detail.json` にあるコースだけを使う。`description` は15〜70字、一文40字以内を目安にする。
そのコースの長さ、幅、地形、接続、圧雪、混雑などを書く。

悪い例:

```json
{
  "name": "サンプルコース",
  "description": "カービングを何度も楽しめる中級コースです。"
}
```

良い例:

```json
{
  "name": "サンプルコース",
  "description": "山頂から麓まで続く圧雪コースで、午後は凹凸が増えます。"
}
```

## 最後の読み直し

JSONを画面に表示される順で読む。各文について次を確認する。

1. 何の話かが最初に分かる。
2. 文末まで読めば、何がどうなるか分かる。
3. 一度読んだだけで意味を言い直せる。
4. ゲレンデの様子か、来場時の行動を思い浮かべられる。
5. そのスキー場だけに残る事実がある。

一つでも満たさない文は、語句を直すだけで済ませず、事実から書き直す。
