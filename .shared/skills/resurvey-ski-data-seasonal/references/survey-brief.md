# 公式サイトの見て回り（survey）の依頼文と結果の形

親は `seasonal.mjs prepare` で作った `brief/<id>.json` を、3スキー場ずつ担当へ渡す。
担当は公式サイトを実際に開いて見て回り、スキー場ごとに `survey/<id>.json` を書く。データは直さない。

## 依頼文

```text
スキー場の公式サイトを見て回り、次の5種類のページが今どこにあるかを調べ直してください。
登録済みのURLが正しいとは限りません。サイトの改修で場所が変わったり、新しいページができていたりします。
登録済みのURLを確かめるだけで終わらせず、必ず公式サイトのトップからメニュー・フッター・スマホ用メニューを辿ってください。

対象と材料: <brief のディレクトリ>/<id>.json（3スキー場）
  - officialSite: 登録済みの公式サイト
  - known: 種類ごとの登録済みのURL
  - leads: 機械的に拾った未登録のページの手がかり（正しいとは限らない。必ず開いて確かめる）

調べる5種類:
  status   その日のコース・リフトの運行状況、天気・積雪、当日の営業コメントが載るページ
  news     お知らせ・ニュースの一覧ページ
  tickets  リフト券の料金表、Web・前売りの購入ページ（シーズン券だけのページ・宿泊や交通付きのパックは除く）
  rental   スキー・スノーボード・ウェアのレンタル料金が載るページ（公式・場内の店）
  map      ゲレンデマップ（コース図）が載るページと、公式が今出している図そのもの

やること（スキー場ごと）:
1. officialSite を開く。別のサイトへ転送される・開けないときは、スキー場名で検索して今の公式サイトを探し、
   施設名・所在地・運営者がそのスキー場と合うことをページで確かめる。
2. トップから5種類のページを探す。Playwright で開き、表示された本文で判断する（要約や検索結果の文面では決めない）。
3. 種類ごとに、known の登録済みURLと比べて verdict を決める。
   - same      登録済みのURLが今もその内容を載せていて、ほかにより適切なページは無い
   - changed   登録済みのURLが無くなった・古い内容のまま・別の場所により適切なページがある（pages に今のURL、note に何が変わったか）
   - new       登録が無かったが、今回ページが見つかった（pages にURL）
   - none      公式サイトのメニューとサイト内を見ても、その種類のページが無い
   - unchecked 調べきれなかった（サイトが落ちている、ログインの先にある等。note に理由と試したこと）
4. tickets は、料金表に書かれているシーズンを season に書く（「2027-28」と書かれていれば "2027-2028"）。
   去年の料金のまま・シーズンの記載が無いなら null。URLの数字や著作権表示の年からは決めない。
5. map は、登録済みの図（known.map.images）が、公式が今出している図と同じかも見る。
   ページは同じでも、図が新しいファイルに差し替わっていれば changed にして、pages に今の図のURLも入れる。
6. status は、オフシーズンで空のことがある。そのときは known.status.previousResearch（前回の調査記録）を読み、
   ページと導線が前回と同じなら same、導線ごと無くなっていれば changed にする。

出力: <brief の output のパス>（スキー場ごとに1ファイル）
{
  "resortId": "<id>",
  "surveyedAt": "YYYY-MM-DD",
  "officialSite": { "url": "<今の公式サイト>", "status": "same | moved | gone", "note": "moved・gone のとき、何を確かめたか" },
  "status":  { "verdict": "…", "pages": [{ "url": "…", "what": "リフト・コースの運行状況", "evidence": "『本日のリフト運行状況』の表" }], "note": "" },
  "news":    { "verdict": "…", "pages": [], "note": "" },
  "tickets": { "verdict": "…", "season": "2027-2028", "pages": [], "note": "" },
  "rental":  { "verdict": "…", "pages": [], "note": "" },
  "map":     { "verdict": "…", "pages": [], "note": "" },
  "findings": ["閉鎖・休止・名称変更・運営の変更など、気づいたこと（あれば）"]
}

pages に入れるのは、今回実際に開いて内容を確かめたURLだけ。what はそのページに何が載っているか、
evidence は判断の根拠にした見出し・表の文言。same のときも、確かめたURLを pages に入れてよい。

守ること:
- 公式サイト（運営会社・自治体のサイトを含む）と、公式ページから案内されているページだけを採る。
  情報サービス・旅行会社・まとめサイトは採らない。URLを推測で組み立てない。
- 料金データ・クローラー・リンクの登録は書き換えない。調べて報告するだけ。
- 開けないページを、開けたことにしない。
最後に、スキー場ごとの verdict の一覧（5種類）と、判断に迷った点を5行以内で返してください。
```

## 親が確かめること

1. `seasonal.mjs audit-survey --ids …` を流す。形の誤りと、報告されたページが開けないものが出る。
   問題が出たスキー場は、指摘を添えて同じ担当へ差し戻す。
2. 1バッチにつき1スキー場、`changed`・`new` のページを自分で開き、`what`・`evidence` のとおりの内容であることを見る。
   3スキー場とも全種類 `same` のバッチは、1スキー場だけ公式サイトのメニューを自分で辿り、見落としが無いかを見る。
3. `officialSite.status` が `moved`・`gone` のスキー場は、後の段階より先に、リンク文書の公式サイトを直す
   （`check-ski-resort-link-health` の「直し方」）。`gone` で今のサイトが見つからないものはユーザーに聞く。
4. `findings` に閉鎖・休止・名称変更があれば、報告に書く（このSkillでは基本情報を直さない）。
