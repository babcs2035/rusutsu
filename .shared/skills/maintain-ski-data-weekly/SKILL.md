# 週次の見回り

このサイトのデータは、公式サイトと外部サイトの今の内容を写したもので、放っておくと古くなる。
週次の見回りは「全部を調べ直す」のではなく、**変わったところと壊れたところだけをスクリプトで見つけ、そこだけを直す**。
スキー場は約450、リンクは数千あるので、エージェントが1件ずつ見て回ることはしない。

## 正本と参照先

このSkillの正本は `.shared/skills/maintain-ski-data-weekly/`。`.agents/skills/` と `.claude/skills/` はシンボリックリンク。

| 必要なとき | 読むもの |
| --- | --- |
| 全種類の点検と報告のまとめ | `scripts/weekly.mjs`（`run` / `summary`）。`mise run maintain:weekly` でも動く |
| 種類ごとの直し方 | 下の表の担当スキルの `SKILL.md` |
| 点検スクリプトの共通処理（API・取得・結果の形） | `scripts/lib.mjs` |
| 既知の問題（分かっていて今は直せないもの） | `src/private/data/maintenance/known-issues.json` |

## 見るもの

| 種類（`--only` の名前） | 何を見つけるか | 担当スキル |
| --- | --- | --- |
| 営業情報クローラー（`crawlers`） | 失敗が続いている・一部を保存できていない・実行が止まっている・警告 | `triage-ski-crawler-health` → 直すのは `fix-ski-resort-latest-crawler` |
| 料金ページ・未登録のページ（`pages`） | 料金の行が変わった・料金表が差し替わった・新しいシーズンの表記・未登録の料金やレンタルや営業情報のページが増えた | `watch-ski-official-pages` → 更新は `collect-ski-lift-ticket-pricing` |
| 雪マジ（`yukimaji`） | 掲載文が変わった・新しく載った・掲載が終わった | `maintain-ski-yukimaji` |
| リンク切れ（`links`） | 切れた・別のサイトへ転送される・トップへ戻される・ドメインが失効した | `check-ski-resort-link-health` → 公式リンクは `collect-ski-resort-official-links` |
| ゲレンデマップ（`maps`） | 表示できない・掲載元から消えた・掲載元に新しい図が増えた・年度が新しい候補がある | `maintain-ski-trail-maps` |
| ツアー・パスの掲載（`listings`） | 載った・載らなくなったスキー場、取れなくなったサイト | `maintain-ski-external-listings` |

見ないもの: スキー場の基本情報（営業期間・閉鎖・名称変更）、天気・積雪・アメダス、レビュー、EV充電、Googleマップ、SNS。
YouTube動画のリンクは数が多く消えにくいので、シーズン前の再調査で見る。

## 手順

1. **点検する。** 全種類で20分ほどかかる（2026-11-26の実測で18分。ツアー会社の巡回と料金ページの描画がそれぞれ12分ほどで、並べて動く）。裏で動かし、終わるのを待つ。

   ```bash
   mise run maintain:weekly
   # 作業領域を決めて動かす・種類を絞る
   node .claude/skills/maintain-ski-data-weekly/scripts/weekly.mjs run \
     --run src/private/data/resorts-temporary/tmp/maintenance/<日付>-weekly [--only crawlers,links] [--skip listings]
   ```

   点検は本番へ書き込まない。書き換えるのは手元の指紋（`src/private/data/maintenance/`、`trail-map-watch/state.json`）と、
   取り直したツアーリンクのファイル（`src/private/data/tour-links/`）だけ。
   `--no-crawl` を付けると、ツアー会社を巡回せずに済ませる（前回の取り直しから日が浅いとき）。

2. **報告を読む。** `<run>/summary.md` に、種類ごとの件数、要対応（高・中）の一覧、次に回す先が出る。
   種類ごとの詳しい結果は `<run>/<種類>/summary.md` と `tasks.json`。同じ報告が
   `src/private/data/maintenance/reports/<日付>-weekly.md` に残るので、前回と比べて増えた指摘を先に見る。
   点検そのものが動かなかった種類は表に「点検できなかった」と出る。`<run>/logs/<種類>.log` で原因を見て、その種類だけ流し直す。

3. **依頼の範囲を決める。**
   - 「点検して」「調べて」: 報告まで。直さない。
   - 「直して」「最新にして」: 手順4まで。本番への反映は、各担当スキルの決まり（差分を確かめてから `--apply`）に従う。
     依頼に反映が含まれるか読み取れないときは、手元のデータを直して差分を出すところまで進め、反映するかを最後に聞く。

4. **種類ごとに直す。** 重さが高のものから、担当スキルの `SKILL.md` を読んで、その手順で直す。順番の目安:
   1. `crawlers` の高（営業中のスキー場で営業情報が出ていない）
   2. `pages` の高（今季料金の発表・料金ページの消失）と中（料金の変化）
   3. `links` の高（ページが無い・サイトが無い）
   4. `maps` の表示できない図
   5. `yukimaji`・`listings` の変化
   6. 残りの中

   プロジェクトの `AGENTS.md` のコスト方針に従う（Claude Code では `sonnet`）。各スキルの `tasks.json` のバッチを、
   そのスキルの依頼文でサブエージェントへ渡す。同時に動かすのは全体で最大2体。原因の判断・差分の監査・反映は親が行う。
   件数が多くても自分の判断で区切らず、未着手が無くなるか、ユーザーの判断が要るものだけが残るまで続ける。

5. **点検し直す。** 直した種類だけ流し直し、報告をまとめ直す。

   ```bash
   node .claude/skills/maintain-ski-data-weekly/scripts/weekly.mjs run --run <run> --only <直した種類>
   ```

   クローラーの修正は、本番の次の定時実行の後でないと結果に出ない。「次の実行待ち」として報告する。

6. **既知の問題を整理する。** ユーザーが「今は直さない」と決めたものを `known-issues.json` に足す（書き方は各担当スキル）。
   既知のものは要対応に数えず、報告の「既知」の欄に理由つきで出る。直ったもの・`until` を過ぎたものは外す。

## 時期と頻度

| 時期 | すること |
| --- | --- |
| 10〜11月（シーズン前） | `resurvey-ski-data-seasonal` で全スキー場を調べ直す |
| 12〜3月（シーズン中） | 週1回、このSkill |
| 4〜5月（シーズン終わり） | 月1回。営業を終えたスキー場のクローラーの警告は、直さずに来季の再調査へ回す |
| 6〜9月 | 月1回、`--only links,maps,listings`（料金とクローラーは動きが無い） |

シーズン前の再調査で「今季料金が未発表」と保留にしたスキー場は、このSkillの `pages` が発表を拾う
（`newer-season`・`season-published`）。拾ったら `collect-ski-lift-ticket-pricing` で集める。

## 完了報告

チャットで、1項目1文の箇条書きで書く。
- 点検した種類と件数、種類ごとの高・中の件数（直す前 → 直した後）。前回の報告から増えた指摘。
- 直したもの（種類ごとに、スキー場と内容）。本番へ反映したもの・手元の修正だけのもの。
- 次の定時実行や次の点検を待っているもの。
- 既知の問題に足したもの・外したもの。
- ユーザーに決めてほしいこと（各行にURL）。
- 点検できなかった種類と理由。指紋・ツアーリンクなど `src/private` の更新が未コミットであること。
