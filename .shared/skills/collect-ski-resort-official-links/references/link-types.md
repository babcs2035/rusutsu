# 種類ごとの載せ方

種類の一覧と並び順の正本は `src/features/resort-links/linkTypes.json`。ここでは、このSkillが集める種類について
「何のページを載せるか」「ラベルをどう付けるか」「迷いやすい境目」を書く。

## 共通

- **その種類が主題のページを載せる。** ページのタイトル・見出し（h1）・URLが、その種類の案内であること
  （キッズなら「キッズパーク」「託児所」、ゲレ食なら「レストラン」「お食事」のページ）。
  コース紹介・よくある質問・トップページ・お知らせ・施設紹介の中に1節や1行あるだけのページは、その種類のページではない。
  例: 志賀高原中央エリアのキッズは、中央エリアのコース紹介の「丸池スノーランド」の節（`shigakogen.co.jp/winter/course/#beginner`）ではなく、
  志賀高原全体の公式サイトのキッズのページ（`https://shigakogen-ski.or.jp/kids/`）。
  運営会社のサイトに専用のページが無ければ、エリア全体の公式サイト（観光協会・索道協会・自治体。リフト券データの出典になっていることが多い）を見る。
  見つけたら `officialSites` に足し、`notes` に理由を書く。どこにも専用のページが無ければ `none`（`note` に「専用の案内なし（コース紹介に1行）」など）。
  サイト全体が1ページだけの小さなスキー場など、その節が唯一の案内のときだけ載せ、`accept` に理由を書く。
- **同じページが別の種類にもあたるとき。** 種類ごとに項目を書く（その種類が主題か、その種類の専用の節があるページに限る）。
  - ゲレンデのタブ（コース情報・パーク・ライブカメラ）: 画面でも種類ごとのボタンにし、それぞれ `quote` の位置へ飛ぶ。`quote` を種類ごとに変える。
  - それ以外のタブ: 画面が1つのボタンにまとめ、名前を「・」でつなぐ（例: 「リフト券・レンタル・Web購入」「アクセス・駐車場」「スクール」）。
    飛び先はページの先頭になるので、`quote` は付けても付けなくてよい。リフト券データ（料金・Web購入・レンタル）や旧リンク（スクール）と同じページでもよい。
    ボタンの名前の順と置く場所は `linkTypes.json` の `samePagePriority`、短い名前は `shortLabel`。長くなる組み合わせは「スクール」のような呼び名か「ほか」にする（`model.ts` の `mergedLinkName`）。
- **1ページ＝1件。** 同じ種類で同じページ（`#…` の位置違いを含む）を指す項目は1件にまとめる。ページ内に出発地・手段・店ごとの節があっても、
  節ごとに項目を増やさない（`quote` は最初の節か、その種類の内容が始まる見出し）。複数件にするのは、ページ（URL）自体が分かれているときだけ。
- **開いて着くページで比べる。** URLの文字が違っても、開くと同じページ・同じ商品に着くなら同じページ。
  例: 志賀高原中央の公式チケットページにあるアソビューのボタン2つ（`/channel/tickets/bZLEert5mh/` と `/channel/tickets/vIh3IOvbXp/`）は、
  掲載元ごとのチャネル番号が違うだけで、どちらも同じ商品 `ticket0000035654` に着く。1件にする（「①②」のように番号で分けない）。
  `audit` が着いたページを比べて `!` を出す（種類が違う場合は、ゲレンデ以外なら画面がまとめるので問題ない）。
- **`label`** は、同じ種類に別々のページが複数あるときの短い名前（出発地・店名・駐車場名・パーク名・サービス名）。1件だけなら付けない。
- **`quote`** は、そのページで該当の内容が始まる場所の短い文字列（見出しなど、ページ本文にそのままある2〜40文字）。
  飛び先を決める手がかりで、ページ全体がその内容なら書かない。場所を CSS で指せるときは `selector` でもよい。
  その内容の始まりにある見出しを選ぶ。一覧の各行に繰り返し出てくる言葉（「特典」「料金」など）は、途中の行に着くので使わない。
  同じ id が何か所にもあるページでは `selector` が別の場所を指すので、見出しの文字で指す。
- **`note`** は、利用者に役立つ一言だけ（「冬は無料」「要予約」「山頂・ベースの2地点」）。画面ではリンクの横に1行で出るので20字ほど、長くても40字まで。
  `found` 以外の項目では、無い・調べきれない理由を書く。調査の経緯は `notes`（ファイル全体のメモ）へ。
- **`label`** も画面ではチップの文字になる。40字まで。
- **`foundOn`** は、公式サイト以外のURLを載せるとき、そのリンクが張られていた公式ページ。
- **今季の情報を載せる。** 古いシーズンのページしか無ければ `note` にシーズンを書く。
- **状態**: `found`＝ある。`none`＝公式サイトを見たうえで無い（パークが無いスキー場のパーク情報など）。
  `unchecked`＝調べきれていない（理由を `note` に）。無いと言い切れないときは `unchecked`。

## ゲレンデ

| 種類 | 載せるページ | ラベル |
| --- | --- | --- |
| `courseInfo` | コースの紹介（コース一覧・難易度・距離など）。紹介ページが無く、マップ掲載ページだけのときはそれを載せ、`note` に「コース紹介はマップのページ」と書く | エリアごとにページが分かれるときはエリア名 |
| `parkInfo` | スノーパーク（キッカー・ジブなど）の紹介 | パークが複数あるときはパーク名 |
| `parkStatus` | パークの当日の状況（アイテムの設置状況など）を出している公式ページ。SNSの投稿を埋め込んで見せている公式ページも載せる。公式サイトに置き場がなくSNSだけで発信しているなら `none` | パーク名 |
| `liveCamera` | ゲレンデのライブカメラ。地点ごとにページやURLが分かれるなら地点ごと | 地点名（山頂、ベースなど） |

## 料金

| 種類 | 載せるページ | ラベル |
| --- | --- | --- |
| `officialDiscount` | 1回行くときに使える公式の割引。前売り・早割・セット券（食事付き・レンタル付き）・宿泊者割・住民割・誕生日割など | 割引の名前 |
| `pass` | 何度も使う券の案内。シーズン券、共通シーズン券、Epic・Ikon・アースホッパーなど共通パスでの利用案内 | 券の名前 |
| `externalDiscount` | 公式ページが案内している、外部サービスの販売・割引ページ（楽天チケット、アソビュー、Klook、ふるさと納税など） | サービス名 |

- リフト券の料金表・自社のWeb販売・レンタル料金は、リフト券データの担当。ここには書かない。
- `externalDiscount` には `category` を付ける。`presale`（国内の前売り・電子チケット）、`inbound`（訪日客向け: Klook・KKday・WAmazing など）、
  `membership`（会員優待）、`transport`（交通とのセット）、`furusato`（ふるさと納税）。
- 割引サイトのクローラー（アソビュー・JAFなど）が取ったリンクは、そのスキー場の公式（リフト券データ・旧リンク・このSkillの収集ファイル）が
  同じタブに同じページを持っていれば、`resort-links:publish -- --source` が反映前に外す（「公式に同じページがあるので外す」と出る）。
- スキー場自身の販売システムは別ドメインでも外部割引ではない（リフト券データのWeb購入）。
  外部サービスの名前で売っているページ（楽天チケット、アソビュー等）が `externalDiscount`。

## 施設

| 種類 | 載せるページ | ラベル |
| --- | --- | --- |
| `restaurant` | ゲレンデ内・ベースのレストラン（ゲレ食）。一覧ページに「スキー場」の節があればそこを `quote` で指す。ホテル内だけのレストランは載せない | 店ごとにページがあるときは店名 |
| `rentalShop` | レンタルのページ（店舗・料金・予約）。画面では料金の「レンタル」ボタンにリフト券データのレンタル料金と合わせて出し、同じページは1つになる。リフト券データに無いときの受け皿なので、公式のレンタルのページを1件載せればよい | 別の店でページが分かれるときだけ店名 |
| `kidsPark` | キッズパーク、そり遊び場、託児 | 施設名 |
| `onsen` | 場内・直営の温泉、日帰り入浴 | 施設名 |
| `lodging` | 直営・公式が案内する提携の宿。宿泊予約サイトの検索結果は載せない | 宿名。多いときは宿泊一覧のページ1件 |

## 車・公共交通

| 種類 | 載せるページ | ラベル |
| --- | --- | --- |
| `carAccess` | 車でのアクセス案内。1ページにまとまっていれば1件（出発地ごとの節・タブがあっても増やさない）。出発地ごとに別ページがあるときだけ、ページごとに載せる | ページが分かれるときだけ出発地（札幌、新千歳空港 など） |
| `parking` | 駐車場の案内（場所・台数・料金） | 駐車場が複数でページが分かれるときは駐車場名 |
| `transitAccess` | 電車・バス・シャトルでのアクセス案内。1ページにまとまっていれば1件（出発地・手段ごとの節があっても増やさない）。別ページに分かれるときだけページごと | ページが分かれるときだけ出発地と手段（札幌（バス）など） |
| `busTimetable` | 公式ページが案内しているバス会社の時刻表ページ | 会社名と路線名 |
| `busTour` | 公式ページが案内しているツアー会社のページ。1社1件で、そのツアー会社サイトのこのスキー場のページ（出発地別・日付入りの検索結果や個別ツアーは使わない）。スキー場のページが無い会社はスキーツアーのトップページ。画面ではツアー会社のクローラー（`crawl:tour-links`）が取った同じ会社のリンクと1つにまとまる | 会社名（`linkSources.json` の表示名と同じ書き方） |

- 交通は冬の運行を確かめる。冬に運休する路線・便は載せない。
- 公式ページが会社名や電話番号だけを書いていてリンクが無いなら、公式のそのページを載せる（外部を検索して補わない）。

## SNS

| 種類 | 載せるページ |
| --- | --- |
| `tiktok` | 公式のTikTokアカウント（公式サイトからリンクされているもの） |

公式サイト（トップ）も `SkiResortLinks.json` の担当で、同じドメインは1件（`/winter/` とトップ、http と https を並べない）。
2件目を置くのは、高鷲スノーパークの高鷲・ダイナ共同サイト（takasudyna.com）のように、別ドメインで載せる価値のあるページがあるときだけ。
同じドメインの重複に気づいたら `legacyFindings` に書く。

X・Instagram・Facebook・LINE・Threads・YouTube は `SkiResortLinks.json` の担当。未登録のアカウントや、
パーク・スクール専用のアカウントを見つけたら `legacyFindings` に書く。
