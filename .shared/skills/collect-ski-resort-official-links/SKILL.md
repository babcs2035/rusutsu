# 公式リンクの収集

スキー場ごとのリンク一覧は、全スキー場で同じグループ・同じ並び順にそろえる。
このSkillは、そのうち「公式サイトから取れる種類」を、公式サイトのページと公式ページに載っているリンクだけから集める。

## 正本と参照先

このSkillの正本は `.shared/skills/collect-ski-resort-official-links/`。`.agents/skills/` と `.claude/skills/` はシンボリックリンク。

| 必要なとき | 読むもの |
| --- | --- |
| 種類ごとに何を載せるか・ラベルの付け方・迷いやすい境目 | `references/link-types.md` |
| 担当エージェントへの依頼文と収集ファイルの形 | `references/agent-brief.md` |
| 調査の材料集め・リンクの監査・飛び先決め | `scripts/official-links.mjs`（`prepare` / `audit`） |
| 形式の検査・本番との差分・反映 | `mise run resort-links:publish -- --official <id...>`（`--check` で形式だけ、`--apply` で反映） |

データ:
- 収集ファイル: `src/private/data/resort-links/<resortId>.json`（Git管理）。反映するのはこのファイルだけ。
- 種類の定義: `src/features/resort-links/linkTypes.json`。`owners` に `officialSkill` がある種類がこのSkillの担当。
  種類を足す・移すときはこのファイルを直す（画面・検査・`prepare` が同じ定義を読む）。
- 反映先: 本番DBの `resort_links`（1リンク=1行）。データAPI経由で、そのスキー場の「公式」の行だけを入れ替える。
  人が管理画面で直した行は入れ替えない。
- 作業領域: `src/private/data/resorts-temporary/tmp/official-links/<run-id>/`（Git管理外）。

## 集めるもの・集めないもの

集めるのは、公式サイト（運営会社・自治体のサイト）のページと、公式ページから張られているリンク。
公式ページに載っていないものは、検索で見つけても載せない。

持ち主が別にいるURLは集め直さない。同じURLを2か所で持つと片方だけ古くなる。

| 集めないもの | 持ち主 |
| --- | --- |
| コース・リフトの営業状況、積雪・天気、お知らせ | 営業状況クローラー（`build-ski-resort-latest-crawler`） |
| リフト券料金、Web購入、レンタル料金 | リフト券データ（`collect-ski-lift-ticket-pricing`） |
| ゲレンデマップと掲載ページ | `maintain-ski-trail-maps` |
| 公式サイト、Googleマップ、スクール、公式YouTube、X・Instagram・Facebook・LINE・Threads、天気サイト | `SkiResortLinks.json`（管理画面のリンク編集） |
| ツアー会社・割引サービスの一覧、道路カメラ、動画サイト、他のまとめサイト | 外部サイトのクローラー（サイトはユーザーが指定する） |

調査中に、上の持ち主のURLの間違いや抜け（SNSの未登録アカウント、切れた公式URLなど）に気づいたら、
収集ファイルの `legacyFindings` に書いて報告する。DBには入れない。

## モデルと分担

プロジェクトの `AGENTS.md` のコスト方針に従う（Claude Code では `sonnet`）。

| 作業 | 担当 | 成果物 |
| --- | --- | --- |
| 材料集め | 親（`prepare`） | `<run>/brief/<id>.json` |
| 1バッチ（最大3スキー場）の調査 | サブエージェント sonnet / low（ページ数の多いサイトは medium） | 収集ファイル |
| リンクの監査と飛び先決め | 親（`audit --write`） | `<run>/audit/<id>.json`、収集ファイルの `jumpUrl` |
| 監査の問題の解消・抜き取りの目視 | 親（直せないものだけ担当へ差し戻す） | 直した収集ファイル |
| 形式の検査・差分の確認・反映 | 親（`resort-links:publish`） | 反映結果 |

同時に動かすのは最大2体。リンクが開けるか・公式ページに載っているか・飛び先は `audit` が確かめるので、
エージェントに同じ確認を繰り返させない。複数バッチの依頼は、全バッチが終わるまで止めない。

## 手順

1. **材料を集める。**

   ```bash
   node .claude/skills/collect-ski-resort-official-links/scripts/official-links.mjs prepare \
     --ids <id,id> --run src/private/data/resorts-temporary/tmp/official-links/<run-id>
   ```

   `brief/<id>.json` に、公式サイト、集める種類の一覧、他で管理中のURL（公式サイト内の入口の手がかり）、前回の収集結果が入る。
   公式サイトが未登録のスキー場は、先に管理画面のリンク編集で公式サイトを登録する（このSkillでは探さない）。

2. **調べる。** `references/agent-brief.md` の依頼文でバッチを渡す。担当は収集ファイルを書く。
   どの種類も「ある（found）・調べたが無い（none）・調べきれていない（unchecked）」のどれかを必ず書く。

3. **監査する。**

   ```bash
   node .claude/skills/collect-ski-resort-official-links/scripts/official-links.mjs audit \
     --ids <id,id> --run <run> --write
   ```

   各リンクをPC（1280×800）とスマホ（375×812）の幅で開き、次を確かめる。
   - 開ける。
   - 公式サイトのページである。公式サイト以外のURLは、`foundOn` の公式ページにそのリンクが載っている。
   - `quote`（該当箇所の見出しなど）がページにある。
   - 飛び先: 開いた最初の画面で該当箇所が見えていれば付けない。下にあるときだけ `#id`、無ければ `#:~:text=`。
     決めた飛び先は開き直し、読み込みが落ち着いた後もその箇所が画面内にあることを確かめる。ずれるページは飛び先なしにする。

   `--write` で `jumpUrl` が収集ファイルに入る。`!` の行が問題。5スキー場で約5分かかる。
   通信が切れて開けなかった項目は、前に決めた `jumpUrl` を消さずに `!` として出る。その場合は時間を置いてやり直す。

4. **問題を解消する。** `!` をすべて読み、URL・`quote`・`foundOn` を直すか、載せるのをやめる。
   直したら 3 をやり直す。`jumpUrl` が付いた項目は、いくつか実際に開いて着地を見る。
   繰り返し出てくる言葉を `quote` にしていて途中の行に着くものは、`quote` を消してページの先頭にする。
   指摘を承知のうえで載せるもの（自動アクセスを拒否するホテルのサイトなど）は、
   項目の `accept` に理由を書く。次回から `~` の行になり、問題の件数に数えない。さらに、種類の違う項目を1スキー場につき3件ほど実際に開き、
   内容がその種類に合っているか（ゲレ食の欄にホテルのレストラン一覧が入っていないか等）を自分の目で確かめる。

5. **差分を見る。** `mise run resort-links:publish -- --official <id...>`。
   形式の検査（書かれていない種類・担当外の種類）と、本番との差分（追加・削除）が出る。

6. **反映する。** 依頼が「調べて」だけなら反映しない。反映まで依頼されていれば `--apply` を付ける。

7. **報告する。** スキー場ごとの found / none / unchecked の件数、`legacyFindings`、人に決めてほしい点（各行にURL）。

## 完了条件

- どの種類にも found / none / unchecked のどれかが書かれている（`resort-links:publish` の検査が通る）。
- `audit` の `!` が0件。承知のうえで残す指摘は、項目の `accept` に理由が書いてある。
- 親が抜き取りで実際の画面を見た項目と、見ていない項目を区別して報告している。
- `unchecked` が残る理由を報告している（サイトが落ちていた、会員ページの中だった等）。

## 人に聞くとき

- 公式サイトが2つあり、どちらが現行か決められない。
- 公式ページが案内する外部サービスが、割引なのか通常の販売なのか読み取れない。
- 冬の運行期間が公式にもバス会社にも書かれていない交通。

質問は各行にURLを付け、候補と自分の案を添える。
