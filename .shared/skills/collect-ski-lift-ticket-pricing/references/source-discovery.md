# 公式URLの探索・確認・登録

Stage 0で読む。検索は候補を探すために使い、登録判断は実際に開いた内容で行う。
既存の登録ファイルは `templates/source-urls.template.json` と互換である。
探索メタデータがない既存エントリも使えるが、今回確認していない内容や確認日を
補完しない。ユーザーが指定したURLの採用基準も同じ。

## 探索範囲

- URLなし、または探索も依頼された収集: 下の検索手順を使う。
- URL指定ありで探索の依頼なし: 指定URLとそこから直接リンクされる公式資料まで。
  既存登録全件や検索結果へ広げない。
- 「指定URLだけ」「このページだけ」: 指定されたURL集合内だけを開き、リンク先も
  追加しない。今回許可されたURL集合を探索結果・台帳に保存する。

範囲限定では `not_checked` の項目に「依頼範囲外」を明記し、許可された範囲の
確認が終わればStage 0を終了できる。確認範囲を広げた探索完了とは報告しない。
抽出中に不足が見つかっても、この範囲を自動で広げない。

## 起点と検索

1. 既存マスタのID・正式名・所在地・旧称・公式サイトを照合する。
   同名施設や旧名称、運営会社の複数施設を混同しない。マスタのURLも古い可能性が
   あるため、開いて施設名・所在地・運営者を確認する。
2. 既存の登録URLを再確認し、料金、購入、営業案内、割引、FAQのリンクを辿る。
   トップページは探索の起点に使えるが、必要な情報がなければ登録しない。
3. 不足する項目を「正式名 + リフト券 料金」「正式名 + 対象シーズン」
   「正式名 + Webチケット / 営業時間 / 割引」等で検索する。
   公式ドメイン判明後はsite検索も使う。URLの文字列を推測して登録しない。
4. 検索・閲覧ツールと、必要に応じてPlaywrightを使う。JS表示、タブ、
   アコーディオン、PDF、画像、ショップの商品詳細まで開いて確認する。
   ツールが利用できない場合はその制約を報告し、未確認を確認済みにしない。

同じ失敗を繰り返さない。通常閲覧・ブラウザ表示など異なる方法でも確認できない
URLは閲覧不能として残す。認証・購入が必要な内容を、未ログインの表示から推測
しない。閲覧に不要な会員登録・購入・問い合わせ送信は行わない。

## 採用できる資料

- スキー場公式サイト、運営会社公式サイト、公式オンラインストア、公式アプリ・
  会員サービスの確認可能な公式ページ。
- 公式PDF・料金画像。別CDNドメインでも、公式の掲載ページから直接案内されて
  いるファイルは採用できる。掲載元を残す。
- 公式サイトから直接案内される外部チケット販売ページ。リンク元を実際に開き、
  リンク先の商品が対象施設の滑走用券であることを確認する。

「公式性」と「必要な内容があること」の両方が必要。公式ストアへのリンクが
あっても、ストアトップに対象商品の情報がなければ対象商品の詳細ページを探す。
自称「公式」、検索順位、ドメイン名の見た目だけでは公式性を確定しない。
自治体直営の施設は、施設名と運営関係を確認できる自治体公式ページも使える。

採用しない:

- シーズン券専用ページ・その保有者だけの特典、観光用ゴンドラ等の非滑走券。
- 旅行会社、宿泊予約、交通・宿泊付きパック、ふるさと納税、一般クーポンサイト。
- 非公式まとめ、ブログ、SNS、Webアーカイブ、スニペットだけの情報。
- 無関係なトップページ、対象内容がないページ、内容を確認できないURL。

日券とシーズン券が同じ料金ページにある場合はページを採用してよいが、抽出する
のは対象券だけ。宿泊者向けのリフト券単体割引と、宿泊込み商品も区別する。
返金されるIC保証金が載った料金ページは採用してよいが、料金合計には含めない。

## 確認項目と終了条件

次の各項目を確認する。券種別に別URLが必要とは限らず、同じページで足りるなら
URLを増やさない。一方、窓口料金だけでWeb料金まで確認済みにしない。

| 項目キー | 確認する内容 |
| --- | --- |
| prices | 料金、年齢・学校区分、日券・時間券・回数券・複数日券・ナイター券・共通券・滑走用セット券 |
| online_sales | Web料金、前売、購入先、販売期間、購入期限、引換方法 |
| operating_schedule | 営業期間、営業日、休業日・定休日、通常・リフト・売場営業時間、ナイター営業日・時間 |
| discounts | 公式割引・会員・地域・学生・子供・シニア・障がい者料金、イベント、資格・必要証明 |
| terms | リフト券FAQ、利用条件、注意事項、券の有効範囲・時間 |
| documents | 公式PDF・画像内の料金表や脚注 |

各項目の確認結果は次のいずれかで記録する:

- `found`: 必要な内容を確認できた。URLと確認箇所を付ける。
- `partially_found`: 一部だけ確認できた。確認済み内容と不足を分ける。
- `not_found`: 公式サイト内の該当導線と不足項目の検索を調べても見つからない。
  「未掲載」と「その券種・割引が存在しない」を同じ意味にしない。
- `not_applicable`: 公式が対象なしと明記している。根拠URLを付ける。
- `unavailable`: 該当候補はあるが内容を開いて確認できない。
- `old_season_only`: 過去資料しか確認できない。実際のシーズンとURLを付ける。
- `not_checked`: まだ調べていない。範囲限定の対象外を除き、これが残る場合は探索未完了。

公式の料金・購入・営業・割引・FAQの導線と不足項目の検索を確認し、関連する
PDF・画像も確認したら探索を区切る。無限に検索を続けず不足を明記する。
URL確認完了は「全券種の情報が揃った」の意味ではなく、確認範囲と不足が明確に
なった状態。料金抽出へ進めるかはStage 1の取得・シーズン判定で別途決める。

## シーズンとURLの整理

- 現在の公式資料を優先する。対象シーズンが未発表なら発表待ちとして残す。
  過去資料は現在の情報がなく確認資料として必要な場合だけ採用し、`label_ja`
  に旧シーズンを明記する。古い情報を今季データへ転記しない。
- 内容のシーズンが不明なら `content_season: null`。サイトの著作権年、URLの
  数字、探索日、営業カレンダーだけから料金表のシーズンを決めない。
- 料金表・商品ごとに異なる年が混在する場合、該当箇所を確認結果へ記録する。
  `content_season` は登録時の参考情報であり、毎回の取得時判定を代替しない。
- リダイレクト後は原則最終URL。同一URL・同一内容の英語版・追跡パラメータを
  除く。商品ID、施設ID、言語以外の価格条件等の機能上必要なパラメータは残す。
- PDF・画像と掲載ページは、脚注・公式性・シーズン確認に必要なら両方登録する。
  URL順は料金 → 購入 → 営業 → 割引・イベント → FAQ・規約 → PDF・画像。

## 保存と既存登録の更新

採用URLは `src/private/data/lift-ticket-source/{resort-id}.json` へ差分登録する。
ID・名称・シーズンをトップレベルへ追加しない。採用URLがゼロなら空の登録
ファイルや架空URLを作らず、探索結果と保留理由を残す。

エントリに記録する項目:

| フィールド | 意味 |
| --- | --- |
| url | 実際に開いて確認できた採用URL |
| label_ja | そのURLで実際に確認できた内容、過去資料なら対象シーズン |
| added_at | 登録日。既存値は保持する |
| discovered_by | 新たなURLを提示した主体: `user` / `agent`。由来不明の既存URLは追加しない |
| verified_at | 今回本文・ファイル・商品内容を確認した日。再確認時に更新する |
| official_basis_ja | 対象施設との一致と公式性を確認した具体的な理由 |
| linked_from_url | 直接案内する公式掲載元。外部販売・CDNファイルでは必須、直接の公式ページではnull可 |
| content_season | 本文から確認できたシーズンID。不明・通年条件ならnull |

これらの追加フィールドは登録ファイル用。料金JSONの `sources` へ独断で追加
しない。既存の `user_specified` は登録URLかどうかを表す互換フィールドとして
維持する。登録後は `capture-sources.mjs` で保存し直した資料を抽出根拠にする。

探索結果は
`src/private/data/resorts-temporary/tmp/lift-ticket-discovery/{resort-id}/{season-id}/discovery.json`
へ保存する。ID・名称・対象シーズン・確認日・調べた導線/検索語・上の6項目の
結果と不足・不採用候補の理由を記録する。確認用画像・本文も同じディレクトリへ
置く。複数件処理では不足と再確認先の要約を進捗台帳にも残し、完了後も追えるようにする。

既存登録を未確認の候補で置換しない。削除は重複・対象外・廃止を確認できたURLに
限る。一時的な閲覧不能だけで既存URLを削除しないが、今回の抽出根拠には使わない。
リダイレクト先への変更も差分と理由を確認する。

## URL調査のみの報告

施設名・ID・対象シーズン、採用URLと確認内容、旧資料・未発見・閲覧不能を簡潔に
報告する。URLは省略せず表示する。通常は登録ファイルへ直接保存し、Writing block
が明示された場合だけ指定形式でも出力する。採用候補に満たないURLを採用一覧へ
混ぜない。料金JSON作成、publishのpull/preview/apply、MISSING.md更新は行わない。
