# UIと公式料金の共通照合

すべてのスキー場で同じ検証項目を使う。対象外の券・未掲載の条件は理由を残す。
公式にない料金を作ったり、大人料金への誤った戻しを「料金が出た」として合格にしない。

## 収集・更新時の共通基準

「テスト済み」は、次の別々の確認を終えたことを指す。料金照会だけ、または
JSONの検証だけを通して、施設全体の確認完了としない。

| 確認 | 毎回の対象 | 保証する範囲 |
| --- | --- | --- |
| 機械検証3本 | 最新草案に validate-lift-ticket / check-taxonomy / check-lift-ticket-coverage | JSONの形式、分類・条件の整合、参照・出典等。公式の金額との一致は別途確認する |
| 独立監査 | 抽出と別の担当が、保存した公式の表・画像・脚注と草案を照合 | 金額・条件の転記と収集範囲。計算処理の正しさは照会で確認する |
| 料金照会 | 最新草案と、公式から独立に作った期待値 | 公開データ変換と画面と同じ計算処理を通した金額・適用条件・出典 |
| 出典リンク | source_quotes の付与・実ブラウザ検証。金額・出典変更後も再実行 | 金額の記載位置へ飛べるか。付与できずページだけを開く料金はその件数を記録する |
| 固定資料の共通テスト | 収集時の照会と同じ期待値を用いたCI用の資料 | 保存した資料に対する再現性。現在の公式サイトを再取得するテストではない |

ここでいう「UI共通照合」はブラウザのクリックや画面描画のテストではない。
画面の表示・操作を変更した場合の実画面確認は、プロジェクトのUI変更手順に従う。
スキルの検証スクリプト自体のテスト（tests/run-tests.mjs）は、検証ロジック等を
変更したときに行い、各施設の公式照合の代わりにしない。
アプリの計算処理を変更した場合は、時間券・早割・人数条件・レンタル等の
該当する機能別テストも実行し、共通照合と合わせて確認する。

### ケース選定と合否

- 下の必須項目を全施設で点検する。各項目を `passed`（照合一致）、
  `failed`（不一致）、`not_applicable`（該当する券・制度なし）、
  `unverified`（根拠不足・未実施）に分け、対象外と未確認には理由を付ける。
  テストランナーのskipは成功件数に含めない。
- 全人物区分の年齢未入力は毎回確認し、掲載された各券種にも公式から転記した
  照合ケースを置く。同じ利用単位の券が1件通っただけでは、別の券も確認済みとしない。
- 条件が同じ組み合わせは代表ケースでよい。金額・対象者・利用可否が変わる条件は
  それぞれ照合し、年齢・日付・時間・販売期限の境界は直前／一致／直後を確認する。
  全条件の総当たりは要求しないが、異なる条件を代表ケースで省略しない。
- 金額だけでなく、0円・年齢入力が必要・料金不明・対象外・休業を区別して照合する。
  公式にない期待額を草案や計算結果から補わない。
- コマンドの終了コード0だけでは完了にしない。現行の共通テストは、未登録の
  施設や利用単位を検出するが、任意のケース配列が空でも全項目の不足を検出する
  わけではない。担当がこの表と実行ケースを照合し、漏れを補う。
- `failed`、必要なケースの未実施、料金計算を左右する未解決事項があれば
  テスト完了・本番反映へ進めない。公式未掲載の運用情報など、既存手順で保留せず
  進められる事項は `unverified` のまま理由を報告し、「全項目合格」と呼ばない。
  checkerの警告も内容を確認し、対応または未解決として残す。

### 結果の記録

施設・シーズンごとに、草案のSHA-256、実行日時・コマンド・終了コード、
成功／失敗／skip件数、上の必須項目別の判定とケース名、公式URL・照合日、
警告・未確認事項を作業領域のテスト結果へ残す。複数件では台帳のartifactsから
参照する。草案を変更したら以前の結果を流用せず、スキルの再検証手順に従う。
完了報告は「機械検証3本／独立監査／草案照会／固定資料テスト／出典リンク」を
分け、失敗・skip・未確認を省略しない。本番反映の成否はテスト結果とは別に報告する。

## 期待値の作成

1. `src/features/lift-ticket/components/TicketPartyEditor.tsx` と、そこから参照される
   `SELECTABLE_TICKET_PARTY_CATEGORIES` を読む。学校区分のIDを直接指定するCLIではなく、
   UIの人物区分・年齢・利用日・滑る長さで入力を作る。
2. 独立監査担当が公式URLの表と脚注から、対象シーズン、日付、人物条件、券種、
   販売経路、期待額を転記する。`utils/testing/officialCases.ts` の共通表へ追加する。
   計算結果から期待額を生成しない。0円、要年齢入力、料金不明、対象外を区別する。
3. CI用に公開データ変換 `toClientLiftTicketData` を通した固定JSONを
   `src/private/data/lift-ticket-test-fixtures/ui/<resort>/<season>.json` に保存する。
   実在スキー場の固定資料は正本とともに `rusutsu-library` で管理し、
   架空データのテスト例のみスキル側の `tests/fixtures/` に置く。
   固定資料と必要な正本の更新をlibrary側でコミットし、親リポジトリでは
   そのコミットへのsubmodule参照と期待値を同時に更新する。
   資料のURL・照合日・未確認事項を残す。

## 必須項目

| 対象 | 確認内容 |
| --- | --- |
| 全人物区分 | 未就学児・小学生・中学生・高校生・大学/専門・大人・障がい者を年齢未入力で照合 |
| 年齢 | 公式の未就学児無料境界、シニア境界の前後。年齢制は必要な入力を求める |
| 学校 | 同じ12歳でも小学生/中学生、18歳でも高校生/大学生の公式条件を分ける。年齢だけで別学年の割引を当てない |
| 障がい者 | UIの追加区分 `baseCategory` で全学校区分を選ぶ。専用料金、対象年齢、証明条件、専用券のない券種の通常料金への戻し |
| 券種 | 日券・時間券・回数券・ナイター・複数日・セット・共通券・追加券のうち掲載された種類 |
| 時間 | UIの時間入力、券の時間境界直前/一致/直後。午後券等を朝から使える券にしない。既知の営業時間を超えた要求に料金を出さない |
| 日付 | 平日・休日・祝日・年末年始・初滑り/通常/春の開始前日/開始日/終了日/翌日 |
| 営業 | 定休日、例外営業日、シーズン開始前/開始日/最終日/終了後。未掲載の営業期間を推測しない |
| 購入 | 窓口/Web、販売開始・終了、購入期限、資格やチャージ券の条件 |
| 人数・複数日 | 親子パック、連続/非連続、時間プール、追加券の前提と合計 |
| レンタル | スキー/ボードで、板だけ・板＋ブーツ・セット・セット＋ウェア・小物を選び、セットと単品の最安の組み合わせ、子供区分、1日/時間/2日間、平休日、Web予約の期限を公式料金表と照合する |
| 出典 | 選ばれた料金行が照合に使った公式URLへ結び付く |

全人物区分を全ての券種で同額にする必要はない。公式にその区分の券がなければ
対象外/未掲載として確認する。日付や券種で条件が異なる場合は代表ケースを増やす。

## 実行

草案は確定版を上書きせず、対象施設の作業領域に一時ルート（例:
`src/private/data/resorts-temporary/tmp/lift-ticket/{resort-id}/staged-ui/`）を作り、
その直下の `{resort-id}/{season-id}.json` にバイト列を保って複製する。
`staged_root` にそのルートを設定し、下の草案用コマンドを使う。
環境変数指定時はルート内にある施設だけを照合するため、全確定版をコピーする
必要はない。公式期待値が未登録なら先に追加する。草案とコピーのSHA-256が一致する
ことと、対象施設のケースが実際に実行されたことを確認し、結果へSHA-256を残す。

```bash
# CIと同じ固定資料の共通テスト（pnpm testにも含まれる）
mise exec -- node --import tsx --test src/features/lift-ticket/utils/uiContract.test.ts

# 作業領域の草案を照合。staged_rootは上記の一時ルートへ設定してから実行する
LIFT_TICKET_DATA_ROOT="$staged_root" mise exec -- node --import tsx --test src/features/lift-ticket/utils/uiContract.test.ts

# 同じ期待値を収集済み全JSONへ適用。未登録のスキー場/シーズンも失敗として検出する
LIFT_TICKET_DATA_ROOT=src/private/data/lift-ticket mise exec -- node --import tsx --test src/features/lift-ticket/utils/uiContract.test.ts
```

CIはライブサイトを取得しない。サイト更新・別シーズンへの切替と実装不具合を分けるため、
公式との再照合は収集・更新時に行い、固定資料と期待値を更新する。
固定資料との一致だけを「現在の公式サイトと一致」と報告してはならない。
全利用単位（`validity.mode`）の確認ケースを必須にし、種類を追加してテストを登録し忘れると失敗させる。

2026-09-26の初回対象は6場。主な公式料金表を照合したものであり、全画像・全キャンペーンの
完全監査ではない。めいほう3歳以下無料は既存の管理者確認で、公式照合済みとして扱わない。
八方の18歳高校生等、公式注記の解釈が曖昧な条件は確定期待額を作らず未解決事項を残す。
