# UIと公式料金の共通照合

すべてのスキー場で同じ検証項目を使う。対象外の券・未掲載の条件は理由を残す。
公式にない料金を作ったり、大人料金への誤った戻しを「料金が出た」として合格にしない。

## 期待値の作成

1. `src/features/lift-ticket/components/TicketPartyEditor.tsx` と、そこから参照される
   `SELECTABLE_TICKET_PARTY_CATEGORIES` を読む。学校区分のIDを直接指定するCLIではなく、
   UIの人物区分・年齢・利用日・滑る長さで入力を作る。
2. 独立監査担当が公式URLの表と脚注から、対象シーズン、日付、人物条件、券種、
   販売経路、期待額を転記する。`utils/testing/officialCases.ts` の共通表へ追加する。
   計算結果から期待額を生成しない。0円、要年齢入力、料金不明、対象外を区別する。
3. CI用に公開データ変換 `toClientLiftTicketData` を通した固定JSONを
   `src/private/data/lift-ticket-test-fixtures/ui/<resort>/<season>.json` に保存する。
   実在スキー場の固定資料は正本とともに `rusutsu-library` で管理し、
   架空データのテスト例のみスキル側の `tests/fixtures/` に置く。
   固定資料と必要な正本の更新をlibrary側でコミットし、親リポジトリでは
   そのコミットへのsubmodule参照と期待値を同時に更新する。
   資料のURL・照合日・未確認事項を残す。

## 必須項目

| 対象 | 確認内容 |
| --- | --- |
| 全人物区分 | 未就学児・小学生・中学生・高校生・大学/専門・大人・障がい者を年齢未入力で照合 |
| 年齢 | 公式の未就学児無料境界、シニア境界の前後。年齢制は必要な入力を求める |
| 学校 | 同じ12歳でも小学生/中学生、18歳でも高校生/大学生の公式条件を分ける。年齢だけで別学年の割引を当てない |
| 障がい者 | UIの追加区分 `baseCategory` で全学校区分を選ぶ。専用料金、対象年齢、証明条件、専用券のない券種の通常料金への戻し |
| 券種 | 日券・時間券・回数券・ナイター・複数日・セット・共通券・追加券のうち掲載された種類 |
| 時間 | UIの時間入力、券の時間境界直前/一致/直後。午後券等を朝から使える券にしない。既知の営業時間を超えた要求に料金を出さない |
| 日付 | 平日・休日・祝日・年末年始・初滑り/通常/春の開始前日/開始日/終了日/翌日 |
| 営業 | 定休日、例外営業日、シーズン開始前/開始日/最終日/終了後。未掲載の営業期間を推測しない |
| 購入 | 窓口/Web、販売開始・終了、購入期限、資格やチャージ券の条件 |
| 人数・複数日 | 親子パック、連続/非連続、時間プール、追加券の前提と合計 |
| 出典 | 選ばれた料金行が照合に使った公式URLへ結び付く |

全人物区分を全ての券種で同額にする必要はない。公式にその区分の券がなければ
対象外/未掲載として確認する。日付や券種で条件が異なる場合は代表ケースを増やす。

## 実行

```bash
# CIと同じ固定資料の共通テスト（pnpm testにも含まれる）
mise exec -- node --import tsx --test src/features/lift-ticket/utils/uiContract.test.ts

# 同じ期待値を収集済み全JSONへ適用。未登録のスキー場/シーズンも失敗として検出する
LIFT_TICKET_DATA_ROOT=src/private/data/lift-ticket mise exec -- node --import tsx --test src/features/lift-ticket/utils/uiContract.test.ts
```

CIはライブサイトを取得しない。サイト更新・別シーズンへの切替と実装不具合を分けるため、
公式との再照合は収集・更新時に行い、固定資料と期待値を更新する。
固定資料との一致だけを「現在の公式サイトと一致」と報告してはならない。
全利用単位（`validity.mode`）の確認ケースを必須にし、種類を追加してテストを登録し忘れると失敗させる。

2026-09-26の初回対象は6場。主な公式料金表を照合したものであり、全画像・全キャンペーンの
完全監査ではない。めいほう3歳以下無料は既存の管理者確認で、公式照合済みとして扱わない。
八方の18歳高校生等、公式注記の解釈が曖昧な条件は確定期待額を作らず未解決事項を残す。
