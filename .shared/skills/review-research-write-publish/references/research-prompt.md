# スキー場レビュー調査・detail.json作成

指定されたスキー場について、**実際に滑走した利用者のレビュー・口コミ・体験談を中心に調査**し、7カテゴリごとに **評価（◎, ○, △）・評価理由・おすすめコース・出典** を記録した `detail.json` を作成する。

目的は、行ったことのないスキー場から行き先を選ぶ人に、**その目的で実際にどの程度楽しめるか**を伝えること。

---

# 1. 最重要原則

`score`、`reason`、`courses` の主根拠は利用者レビューとする。

公式サイト・自治体・観光協会等は、以下の**存在・現行性確認**に使う。

* 現行コース名
* 距離・斜度
* 圧雪・非圧雪
* 公式ツリーラン
* パーク
* 新設・廃止

公式情報だけから「充実している」「楽しい」「おすすめ」と評価してはならない。

禁止例：

* 初級コースが多いから beginner を◎
* 中級コースが長いから intermediate を◎
* 最大斜度が高いから advanced を◎
* 非圧雪コースが多いから powder を◎
* ツリーランが広いから tree-run を◎
* アイテム数が多いから park を◎
* ゲレンデマップを見て「良さそう」と判断したコースを `courses` に入れる

公式情報は、利用者レビューを探す手掛かりや、レビュー内容の事実確認に使う。

**公式情報に掲載されているだけで現在存在すると判断しない。**
公式情報に加え、原則として直近のレビュー・ブログ・滑走記録・SNS・YouTube等でも実際に滑走・利用されていることを確認する。公式情報と利用者情報が食い違う場合は追加調査する。

---

# 2. 出力構造

```json
{
  "resortId": "resort-slug",
  "research": { "date": "YYYY年M月D日", "note": "調査全体の状況" },
  "beginner": {
    "score": "○",
    "reason": "評価理由",
    "courses": [
      { "name": "コース名", "description": "そのカテゴリでの利用者評価", "sources": [] }
    ],
    "sources": [],
    "warn": false,
    "warnReason": null
  },
  "intermediate": {}, "advanced": {}, "moguls": {},
  "powder": {}, "tree-run": {}, "park": {}
}
```

7カテゴリすべてを同じ形で含める。独自キーは追加しない。

## sources

```json
{
  "type": "review",
  "url": "https://...",
  "description": "内容の説明。投稿時期を含める",
  "quote": "実在する原文引用。なければ空文字"
}
```

`type` は `"review"` または `"official"`。

review の `quote` は元ページ本文に実在する文章のみ。自分の要約を入れない。

official は `quote` 不要。`description` に確認した事実と確認日を書く。

---

# 3. courses の選定ルール

`courses` には、**そのカテゴリで利用者から実際におすすめされている、繰り返し滑られている、または具体的に高く評価されているコース・エリア**を書く。

公式ゲレンデマップやスペックだけを見て、推測して追加してはならない。

ただ、カテゴリとコース難易度・性質が明確に一致しない場合は、単に「おすすめ」と書かれているだけでは courses に採用しない。

例えば、beginner では、公式中級・上級コースを、記事やレビューで「初心者にもおすすめ」「ファミリー向け」と紹介されているだけで courses に入れてはならない。
採用するには、初心者本人、または初心者に同行した利用者が、そのコースを実際に滑ったうえで「怖くない」「練習しやすい」「初心者でも問題なく滑れた」等の具体的な体験を記録していることを原則とする。

intermediate・advanced についても同様に、カテゴリと公式難易度がずれるコースを採用する場合は、そのレベルの利用者が実際に滑った具体的な根拠を必要とする。

`courses[].description` は公式スペックの説明ではなく、**そのカテゴリで利用者がどう評価しているか**を中心に書く。

利用者レビューからおすすめコースを確認できない場合は、公式マップから推測して埋めず、`courses: []` としてよい。

---

# 4. 評価基準

| score | 基準 |
| ----- | ---- |
| ◎ | そのカテゴリに明確な魅力があり、複数の独立した利用者から繰り返し高く評価されている |
| ○ | そのカテゴリを十分楽しめる対象を確認できる |
| △ | 十分調査しても対象が成立していない、ほとんど成立していない、または継続的に楽しめる対象を確認できない |

**情報が少ないこと自体を理由にscoreを下げない。**

禁止：

* レビューが少ないから△
* 1件しかないから△
* 自信がないから△
* 他にもあるか不明だから△

不確実性は `warn` で表す。

advanced・moguls・tree-run・park は1コース・1エリアでも十分楽しめれば○以上になり得る。ただし、**現在実際に存在・利用されていることを公式情報と利用者情報の両方で確認する。**

---

# 5. 「ある」と継続性

コブ等の変動対象は、利用者1人の単発記録だけで継続的に「ある」と断定しない。

継続的なコブとして採用するには、以下のいずれかを確認する。

* 公式にモーグル・コブコースとして扱われ、レビューから直近の利用実績も確認できる
* 異なる利用者・日・シーズンから同じ場所のコブが繰り返し確認できる

パーク・ツリーラン等も、古い公式ページだけで現行と判断せず、直近の利用実態を確認する。

---

# 6. 「ない」「少ない」「1か所だけ」

以下を書く前には必ず追加調査する。

* ない
* 存在しない
* ほとんどない
* 少ない
* 1か所だけ
* 1コースだけ

最初の検索で見つからなかっただけで判断しない。

別コース名、エリア名、旧名称、別媒体、別年代、日本語・英語、ブログ、SNS、YouTube、滑走記録等でも調べる。

十分調査しても確認できず、存在しないことを直接確認できない場合は、**「調査した範囲では確認できなかった」**と書く。

特にコブは1か所見つけても探索を終了せず、他コースも調査する。

---

# 7. reason

`reason` は記事ではなく調査記録。目安400〜1200字。

必ず以下を含める。

1. 利用者から中心的に評価されている内容と具体的コース名
2. 何人程度・何年・どの媒体で確認したか
3. 弱点・制約・人を選ぶ点
4. 意見が分かれる場合はその内容
5. **なぜそのscoreにしたのか**
6. 判定に迷った点・確認できなかった点

弱点を探しても見つからなければ、その旨を書く。弱点を作り出さない。

公式のコース数・距離等だけをreasonの中心にしない。

---

# 8. 情報源

主に使うもの：

* スキー場レビューサイト
* Google等の施設口コミ
* じゃらん、Tripadvisor等
* 個人ブログ
* 滑走記録
* SNS
* YouTube
* 実際の滑走体験談

公式情報は客観的事実と現行性確認に使う。

公式の「初心者におすすめ」「極上パウダー」「上級者も満足」等の宣伝表現を利用者評価の根拠にしない。

検索結果スニペットだけを根拠にせず、必ず元ページ本文を開き前後の文脈を確認する。

* 後続文で否定されていないか
* 特定日の天候・雪質だけの話ではないか
* 対象コースや利用者レベルを取り違えていないか
* 一部の話をスキー場全体へ一般化していないか

閲覧できない投稿は使わない。

---

# 9. 一時的状況

以下は原則として恒久評価に使わない。

* 特定日の雪質・気温
* 強風
* 一時的なリフト停止
* 故障・事故・大会
* 一時的混雑
* シーズン末の雪不足による閉鎖

複数年・複数利用者から同じ傾向が確認できれば構造的特徴として使える。

powder は降雪日の体験を、雪が溜まりやすい場所・残りやすさ・競争率等の判断に使ってよい。ただし特定日の雪質を恒常化しない。

---

# 10. beginner

**初心者の実体験を中心に評価する。**

レビューで見るもの：

* 滑りやすさ・練習しやすさ
* 怖い区間の有無
* 十分長く楽しめるか
* 選択肢があるか
* 移動・リフト乗降
* 他レベルとの動線

公式の初級コース数・距離・斜度は補助情報にとどめる。

◎：初心者本人・同行者から、滑りやすさ、練習環境、距離・選択肢等が複数の独立した利用者から繰り返し高評価。

○：初心者が問題なく十分楽しめることを確認できる。

△：十分調査した結果、初心者が継続して滑れる場所がほとんどない、避けにくい急斜面等の大きな構造的制約がある。

---

# 11. intermediate

**中級者向け圧雪コースを評価する。**

レビューで、クルージングの楽しさ、滑走距離、バリエーション、反復価値、単調・短い等の指摘を確認する。

公式の中級コース数・距離は補助情報にとどめる。

◎：距離・バリエーション・滑走感等が複数の独立した利用者から繰り返し高評価。

○：中級者が十分楽しめる圧雪コースを確認できる。

△：十分調査しても中級者が継続的に楽しめる圧雪コースをほとんど確認できない。

---

# 12. advanced

**上級者向け圧雪急斜面のみ評価する。** 目安25度以上。中級表記でも十分な急斜面と確認できれば含めてよい。

非圧雪・コブ・ツリーラン・パウダーを混ぜない。

レビューで圧雪急斜面の滑り応え、距離、楽しさ、反復価値を確認し、斜度・圧雪状況は公式で補助確認する。現在も同じ運用か直近の利用記録でも確認する。

◎：魅力ある圧雪急斜面があり、複数利用者から繰り返し高評価。

○：現在、上級者が十分楽しめる圧雪急斜面を確認できる。

△：十分調査しても確認できない、または極めて限定的。

---

# 13. moguls

対象は、常設コブ、モーグルコース、シーズン中に継続して作られる明確なコブライン。単なる荒れた斜面・当日だけの凹凸は除外。

コブの場所、長さ、ライン数、難易度、継続性、コブ利用者の評価を調べる。

◎：継続的なコブがあり、複数のコブ利用者から繰り返し高評価。

○：現在も継続的に存在するコブを1か所以上確認できる。

△：検索語・媒体・コース名を変えて十分調査しても継続的なコブを確認できない。

1か所見つけても他コースを追加調査する。

---

# 14. powder

非圧雪コース・管理区域内のパウダーエリアを評価する。

レビューで、実際に狙われる場所、雪の残りやすさ、競争率、地形、満足度を確認する。

公式の非圧雪コース数だけで高評価にしない。

◎：パウダーを狙える場所が充実し、複数利用者から繰り返し高評価。

○：継続的にパウダーを狙える場所を確認できる。

△：十分調査しても継続的に狙える場所をほとんど確認できない。

---

# 15. tree-run

**公式に許可・管理されたツリーランのみ評価する。**

通常の林間コース、コース脇、管理区域外、非公式バックカントリーは除外。

最新公式情報で許可状況を確認し、さらに直近の利用者情報から実際に利用されていることも確認する。

レビューで木の間隔、地形、雪、広さの体感、難易度、楽しさを確認する。

◎：現在利用可能な公式ツリーランがあり、複数利用者から繰り返し高評価。

○：現在利用可能な公式ツリーランを1エリア以上確認できる。

△：十分調査しても現在利用可能な公式ツリーランを確認できない。

---

# 16. park

継続設置されるキッカー・BOX・レール・ハーフパイプ等を評価する。一時的イベントや自然地形だけの場所は除外。

公式情報で設置状況を確認し、直近の利用者情報から実際に利用されていることも確認する。

レビューでアイテム構成、サイズ、難易度、整備、楽しさを確認する。

◎：現在パークがあり、内容について複数利用者から繰り返し高評価。

○：現在継続設置されているパークを確認できる。

△：十分調査しても現行パークを確認できない。

---

# 17. 調査量

目標：

* リフト4本以上：全体40〜60件
* リフト3本以下：全体25〜35件

主に**利用者情報**を調べる。公式ページを多数確認して件数を満たしたことにしない。

カテゴリ単位の最低件数は設けない。不足時は検索語・媒体・年代・コース名を変える。それでも不足する場合は `research.note` に記録する。

原則として直近5シーズンを中心に調査する。

---

# 18. warn

`warn` はscoreとは別に根拠の不確かさを示す。

`warn: true` の例：

* 主要根拠が独立1件のみ
* 情報が古く現行性が不明
* 意見が大きく分かれる
* コブの継続性が弱い
* 公式情報と利用者情報が食い違う
* 他にも対象がある可能性を排除できない

根拠が少ないことを理由にscoreを△へ落とさない。`warnReason` に具体的な不確実性を書く。

---

# 19. 調査手順

1. 対象スキー場・対象エリアを確定
2. 公式情報で現行コース・設備・圧雪等を確認する。**この段階でscoreやおすすめコースを決めない**
3. 利用者レビューを広く収集
4. 各カテゴリについてレビューを個別調査
5. レビューに出たコース名・候補コース名で追加検索
6. `courses` は利用者評価が確認できたコースだけから選定
7. 「ない・少ない・1か所だけ」の場合は検索語・媒体・年代を変えて追加調査
8. advanced・moguls・tree-run・park は公式情報と直近の利用者情報の両方で現行性を確認
9. 一時的要因を除外
10. 利用者評価を中心にscoreを決定
11. 不確実性をwarnに記録
12. 引用の原文・文脈を再確認し、JSONとして検証

---

# 20. 最終確認

* 7カテゴリすべてに必要キーがある
* scoreは◎○△のみ
* `score`・`reason`・`courses` の主根拠が利用者レビュー
* 公式スペックだけでscoreを上げていない
* `courses` を公式ゲレンデマップやスペックから推測して選んでいない
* `courses` は利用者から実際に評価されたおすすめコース・エリアのみ
* beginnerをコース本数だけで評価していない
* intermediateを本数・距離だけで評価していない
* advancedに非圧雪・コブ・ツリーランを混ぜていない
* mogulsは単発の荒れを採用していない
* コブを1か所見つけても探索を終了していない
* tree-runは公式ツリーランのみ
* parkは継続設置のみ
* advanced・moguls・tree-run・park の現行性を公式情報だけで判断していない
* 「ない・少ない・1か所だけ」の前に追加調査している
* 情報不足だけでscoreを下げていない
* 弱点を作り出していない
* 一時的状況を恒久評価していない
* reviewのquoteは実在する原文
* officialは客観情報と確認日を記載
* JSONとしてパースできる

# 最重要原則

**公式情報は「何があるか」を確認するために使い、利用者レビューは「それが現在実際に使われているか」「どの程度楽しいか」「どのコースがおすすめか」を評価するために使う。**

存在しない情報を作らない。慎重さだけを理由にscoreを下げない。公式スペックだけを理由にscoreを上げない。公式マップだけを見ておすすめコースを作らない。
