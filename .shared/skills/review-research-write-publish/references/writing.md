# article.json の書き方

## 誰がどう読むか

読むのは、そのスキー場へ行ったことがない人。スマホの詳細画面でカテゴリ（初心者・コブなど）を
開き、数秒で「自分の目的に合うか」を判断する。箇条書きは頭から順に読まれず、拾い読みされる。

だから1項目は、**その1行だけ読んで、どこの・何の話で・自分にどう関係するかが分かる**ように書く。

画面には次の順で出る。

```
（見出しなしの1行）  ← label: description
良い点              ← label: good
気になる点          ← label: bad
代表的なコース      ← courses
```

## 読みにくくなる原因と、その直し方

これまでの記事が読みにくかった原因は6つある。どれも「文法の誤り」ではなく、
読み手に渡す情報が減っていることが原因だった。

### 1. 場所を名前で言う

名前を伏せると、読み手は地図のどこの話か分からない。

| 読みにくい | 読みやすい |
| --- | --- |
| 初心者向けの斜面は穏やかな山にまとまっているので、家族で同じ場所にいられます。 | 初心者向けの緩斜面はホテル前のWest Mt.に集まっていて、家族が別々の山に分かれずに済みます。 |
| もう一本の上級斜面は降雪時に下部まで非圧雪になるため、… | ぶなコースは雪が降ると圧雪されないので、… |

山・エリア・ゲレンデ・コースの名前は、理由欄（`reason`）にも全体欄（`full`）にも書いてよい。
初めて出る名前には、位置づけを一言添える（「ホテル前のWest Mt.」「一番奥のMt.イゾラ」）。
`detail.json` に位置づけがなければ、名前だけでよい。

### 2. 後半には「誰が・いつ・何が変わるか」を書く。無ければ事実で止める

1項目の基本形は **事実＋それが読み手にとって何を意味するか**。ただし後半は
`detail.json` に書かれている体験からだけ作る。材料が無いのに後半を付けると、
どのスキー場にも当てはまる決まり文句になり、しかも裏付けのない主張になる。

| 決まり文句の後半 | 直し方 |
| --- | --- |
| 中級の圧雪コースが何本もあり、一日飽きずに回せます。 | 中級の圧雪コースは山頂から麓まで約2kmあり、途中で止まらずに滑り切れます。（数字で言う） |
| 最大35度の急斜面が整備されているため、思い切り飛ばせます。 | ブナ坂第2コースは最大35度あり、朝のうちは圧雪された状態で滑れます。（条件で言う） |
| 公式のツリーラン区域がないので、樹林目的だと行き先が残りません。 | 公式のツリーラン区域はありません。（事実で止める） |

後半が役に立つのは、次のどれかを言えているとき。

- 誰にとってか（初めて板を履く人、子ども連れ、コブを覚えたい段階の人）
- いつ・どの条件でか（休日、降雪の翌朝、10時以降、3月）
- 当日の動きがどう変わるか（朝のうちに滑る、移動に時間を取られる、受付が要る）

確かめ方は2つ。**後半を消して情報が減らないなら、後半は要らない。**
**スキー場の名前を別のスキー場に替えても通じる文は、何も伝えていない。**

数字（距離・斜度・本数・時刻・月）は、文を具体的にする一番の近道になる。
`detail.json` にある数字は積極的に使う。無い数字は書かない。

### 3. その読み手が知っている言葉で書く

調査メモや滑り慣れた人の言葉が、そのまま記事に残りやすい。

| 内輪の言葉 | ふつうの言葉 |
| --- | --- |
| 回す、回せる | 繰り返し滑る、何本も滑る |
| 朝いち | 朝一番（リフトが動き始めてすぐ） |
| ノートラック | まだ誰も滑っていない雪 |
| 食われる、食い荒らされる | 滑り跡だらけになる |
| 一枚バーン | 幅が広く、途中で折れ曲がらない斜面 |
| 攻める、飛ばす | スピードを出して滑る |
| 漕ぐ | 板を履いたまま歩く、ストックで押して進む |
| 滑り込む | 何本も練習する |
| 当たる、当てる（新雪に／アイテムに） | 滑れる、使える |

カテゴリごとに読み手が違う。`beginner` を読む人は初めて行く初心者か、その連れなので、
一番やさしい言葉で書く。`moguls` や `park` を読む人は、コブライン・キッカー・ジブを知っている。
圧雪・非圧雪・コブ・パウダー・リフトの種類は、どのカテゴリでもそのまま使ってよい。

### 4. 調査の事情は書かず、読み手の行動に直す

`detail.json` は調査記録なので「確認できなかった」「レビューが少ない」が書いてある。
それは読み手の役に立たない。

| 調査の事情 | 直し方 |
| --- | --- |
| どの初級コースが滑りやすいかまでは分からないので、着いてから様子を見ることになります。 | 書かない |
| 次のシーズンにアイテムが置かれるかは分かりません。 | キッカーは置かれない年もあるので、行く前に公式サイトで設置を確かめてください。（確かめる物が具体的なら、行動として書く） |

主張の強さは裏付けに合わせる。

| `detail.json` での裏付け | 記事での書き方 |
| --- | --- |
| 複数の人・複数のシーズンで同じことが書かれている | 言い切る |
| 条件があるときだけ起きる | 条件を文の頭に置く（「休日は」「雪が降った翌朝は」） |
| 1人が1回体験しただけ | 全員に起きることとして書かない。来場判断を変える内容なら「〜ことがあります」で1回だけ書き、そうでなければ書かない |
| 分からない | 書かない |

1人が「半日で滑れるようになった」と書いていても、「半日で滑れるようになります」とは書けない。

「公式の案内に無い」と「存在しない」も別のことである。`detail.json` が「確認できなかった」と
書いているなら、「公式のゲレンデマップにツリーラン区域の表示はありません」のように、
確かめた範囲をそのまま言う。「ありません」と言い切れるのは、無いことを示す記述があるときだけ。

1日だけの記録でも、行き先選びに効くなら、起きたこととして書けばよい。

| 言い過ぎ | 起きたこととして書く |
| --- | --- |
| 寺小屋クワッドは朝に混み、10〜15分待ちます。 | 寺小屋クワッドは混むことがあり、10〜15分待った日もあります。 |
| ぶなコースは滑る人が少なく、新雪が残ります。 | ぶなコースは、新雪が約30cm積もった日にふわふわの雪を滑れた斜面です。 |

### 5. 同じことを二度書かない。書くことが無ければ1行で終える

- `△` で対象が無いカテゴリは、1〜2項目でよい。「ツリーランはありません」を言い方を変えて
  3回書かない。
- `full` は各カテゴリの言い直しではない。下の「欄の役割」を見る。
- `reason` と `courses` で同じ説明を繰り返さない。

### 6. 話題を先頭に置き、まっすぐ言い切る

拾い読みする人は、各項目の最初の数文字で読むかどうかを決める。

- 項目の先頭に、何の話か（場所・対象・条件）を置く。
- 主語と述語を近づける。名詞の前に修飾を3つ以上重ねない。重なったら文を分けるか、
  修飾を述語側へ回す。
- 1項目に用件は1つ。2つあるなら2項目にする。
- 否定は「ありません」「できません」と言い切る。「〜わけではありません」「〜とは限りません」は、
  何が起きるのかを読み手に考えさせる。
- 「〜ことがあり、〜場合があります」のように、ぼかしを重ねない。

| 読みにくい | 読みやすい |
| --- | --- |
| 山頂から麓まで続く幅の広い圧雪された急斜面を滑れます。 | 山頂から麓までの急斜面は幅が広く、毎日圧雪されます。 |
| 圧雪を入れる時間帯が滑走中と重なることがあり、整った雪面をいつでも滑れるとは限りません。 | 営業中に圧雪車が入ることがあり、その間はコースの一部を滑れません。 |
| 人気の斜面は平日でも10時ごろには良い場所が踏まれ、朝いちの動き方で差が付きます。 | 新雪の斜面は平日でも10時ごろには滑り跡だらけになるので、狙うなら朝一番に向かいます。 |

全部の項目が「〜ため、〜できます。」の形になると、違いが目に入らなくなる。
型をそろえるのではなく、項目ごとに言うべき内容へ合わせる。短い言い切りが混ざってよい。

## 欄の役割

| 欄 | 役割 | 項目数 |
| --- | --- | --- |
| `full` | このスキー場は誰に向き、誰には向かないか。行き先選びの結論 | 3〜5 |
| 各カテゴリの `reason` | その目的で来た人にとって、何がしやすく、何が負担・制限になるか | ◎○は2〜4、△は1〜2 |
| 各カテゴリの `courses` | そのコースはどんな斜面で、誰がどの段階で使うか | `detail.json` の `courses` と同じ顔ぶれ |

### full

先頭に `description` を1項目置き、**どんな人に一番向くスキー場かを一言で**言う。
続けて、行き先選びを最も左右する強みを `good` で2〜3項目、旅行の計画を変える制約
（移動・混雑・目的の設備が無い）を `bad` で1〜2項目。7カテゴリを網羅しない。

カテゴリ側と同じ文を置かない。`full` は「だから誰が行くとよいか」を、カテゴリ側は
「現地で何が起きるか」を書く。

### reason

1項目目で、そのカテゴリの結論が分かるようにする（友人に「あそこ、コブはどう？」と
聞かれて最初に答える一言）。`score` の記号は書かない。

`description` は良し悪しを付けない営業条件（期間・時刻・場所）に使う。使わなくてよい。

### courses

`name` は `detail.json` の `courses` と同じ名前。`description` は1文で、どんな斜面か
（幅・長さ・斜度・雪）と、誰がどう使うかを書く。`detail.json` で利用者がそのコースについて
語った内容から作り、公式のスペックだけの紹介にしない。

## 文の形

- 敬体（です・ます）。1項目は1文、句点で終える。
- 25〜60字を目安に、長くても80字。短い言い切りは15字程度でもよい。
- 前の項目を読まなくても意味が通る。「また」「一方」「これ」で始めない。
- 年・媒体名・レビュー件数・引用・「〜と評価されています」は書かない。

## 書く手順

1. カテゴリごとに `detail.json` の `reason` と `courses` から、記事に使う事実を拾う。
   拾うのは、場所の名前、数字、条件（時期・時刻・天候・曜日）、誰の体験か、裏付けの数。
   調査の経緯、採点の理由、引用は拾わない。
2. そのカテゴリの結論を、友人に話すつもりで一度言葉にしてから、敬体の文にする。
3. 残りの項目と `courses` を書く。
4. 7カテゴリを書き終えてから `full` を書く。
5. `score`・`warn`・`warnReason` は `detail.json` から写す（画面には `warnReason` は出ない）。

## 読み直し

`check-review.mjs --print` で画面と同じ並びに出して、通しで読む。

1. 声に出す速さで読み、読み返した箇所を直す。語を差し替えるのではなく、
   `detail.json` に戻って言い直す。
2. 各項目について、後半を消しても情報が減らないか、スキー場名を替えても通じてしまわないかを見る。
3. 各項目の事実（名前・数字・条件・強さ）を、`detail.json` のどの記述から取ったか指させるか確かめる。
   指させない文は消す。
4. 同じ言い回しと同じ内容が、欄をまたいで繰り返されていないか見る。

## 見本

志賀高原 中央エリアの `beginner`（◎）を、この書き方で書いた形。数字と名前は
`detail.json` にあるものだけを使う。

> **良い点**
>
> - 一の瀬ファミリーの正面ゲレンデ下部は幅が広く、初めて板を履く人が人を避けずに練習できます。
> - 天狗コースは山頂から麓まで3.2km緩やかなままなので、ターンを覚えたら山頂まで上がれます。
> - 蓮池は緩斜面が中心で人が少なく、一の瀬が混む日の練習場所になります。
>
> **気になる点**
>
> - 一の瀬ファミリーの正面上部は急斜面なので、山頂からは天狗コースへ回ります。
> - スキー教室の団体が入る時間は、一の瀬と高天ヶ原のリフトが混みます。
>
> **代表的なコース**
>
> - 一の瀬ファミリー 天狗コース：3.2kmの林間コースで急な所が無く、初級者が初めて山頂から下りる一本に向いています。
