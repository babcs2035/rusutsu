# 担当への依頼文（変化が本当の変更かを見分ける）

親は `tasks.json` のバッチ（最大5スキー場）を1つずつ渡す。担当は料金データを書き換えない。見分けて報告するだけ。

## 依頼文

```text
スキー場の公式ページで、前回の点検から変化があった箇所を渡します。
それぞれが「料金・条件の変更」なのか、そうでないのかを、ページを実際に開いて見分けてください。

入力: <run>/pages/tasks.json の batch "<batch>"
  - changes: 料金ページごとの、増えた行（added）と消えた行（removed）
  - newPages: 公式サイトに増えた、未登録のページへのリンク（cat = ticket / rental / status / map）
手元の料金データ: src/private/data/lift-ticket/<id>/<season>.json（今の登録内容。読むだけ）

やること:
1. changes のURLを開き、added・removed の行がページのどこにあるかを見つける。
2. その行が、手元の料金データにある券種・区分・料金・期間・購入条件のどれかと食い違うかを確かめる。
3. newPages のURLを開き、何のページかを確かめる。

判定:
- changed: 料金・券種・年齢区分・販売期間・営業期間・割引の条件が、手元のデータと違う。
- not-changed: 料金に関係のない行（告知・在庫・並び順）が変わっただけ。または、データは既にその内容になっている。
- unsure: ログインや購入手続きの先で見えない、PDF・画像が読めない、など。理由を書く。
newPages は、relevant（そのスキー場の料金・レンタル料金・営業情報・ゲレンデマップが載っている）か
not-relevant（別の施設・夏の営業・スクール・既に登録済みのページと同じ内容）かを書く。

出力: <run>/pages/verdicts/<batch>.json
[
  {
    "id": "<resort-id>",
    "changes": [
      { "url": "…", "verdict": "changed", "what": "大人1日券が6,500円→6,800円。シニア券が新設", "evidence": "料金表の『大人 1日券 6,800円』の行" }
    ],
    "newPages": [
      { "url": "…", "cat": "rental", "verdict": "relevant", "what": "スキーセット・ボードセット・ウェアの1日料金表" }
    ]
  }
]

守ること:
- ページに書かれていることだけを根拠にする。検索結果の要約や推測で判定しない。
- 料金データのファイル・公式URLの登録ファイルは書き換えない。
- 開けないページは unsure にして、何を試したかを書く。
最後に、changed・relevant・unsure の件数と、判断に迷った点を3行以内で返してください。
```

## 親が確かめること

- `changed` の `evidence` が、実際の `added`・`removed` の行と対応していること。
- `not-changed` が半数を超えるスキー場は、指紋の取り方に合わないページ（毎回並びが変わる等）かもしれない。
  同じURLが2回続けて `not-changed` なら、既知の問題に足すかをユーザーに聞く。
