# detail.md のフォーマット

各カテゴリの `src/private/data/reviews/<slug>/<category>/detail.md` は、次の構成で作成する。
既存スキー場（例: `rusutsu-resort/advanced/detail.md`）の書式に厳密に合わせること。

## 全体構成

```markdown
# <スキー場名> — <カテゴリ日本語名>調査詳細

- **正式名称：** ...
- **所在地：** ...
- **調査フェーズ：** フェーズ1（利用者レビュー調査）
- **調査日：** YYYY年M月D日
- **調査方針：** 直近5シーズンの利用者レビューを優先し、古い情報は現在も変わりにくい
  地形・コース構成の補強に限定した。当日の天候、降雪量、雪質、イベントによる規制は
  恒久的評価から除外した。
- **公式情報の扱い：** コース名、現行コース区分、パーク構成、指定ツリーラン区域、
  安全ルールの確認にのみ使用し、利用者評価の根拠にはしていない。
- **全体で確認した独立利用者ソース：** N件（同一投稿者の複数投稿は1件として集計）
- **本カテゴリに関連した独立利用者ソース：** M件

## 良い評価

- **主張：** 具体的な内容
    - **確度：** 高 / 中 / 低
    - **根拠：** 複数ソースからこの判断を導いた理由
    - **ソース：** 「短い原文引用」（出典タイトル、投稿日、URL）
    - **ソース：** 「短い原文引用」（出典タイトル、投稿日、URL）

## 悪い評価

- **主張：** 具体的な内容
    - **確度：** 高 / 中 / 低
    - **根拠：** 複数ソースからこの判断を導いた理由
    - **ソース：** 「短い原文引用」（出典タイトル、投稿日、URL）
    - **ソース：** 「短い原文引用」（出典タイトル、投稿日、URL）

## コース別情報

**コース名またはエリア名**
- **特徴：** ...
- **利用者評価：** ...
- **確度：** 高 / 中 / 低
- **根拠ソース：**
    - 「短い原文引用」（出典タイトル、URL）

## 判断を保留した内容

- 根拠が弱く採用しなかった主張、独立ソースが不足している点などを箇条書きで記録する。
```

## 書き方の注意

- 「全体で確認した独立利用者ソース」はスキー場全体（7カテゴリ合計、重複排除後）の件数。
  カテゴリごとに書く数値は同じ値を転記する。
- 「本カテゴリに関連した独立利用者ソース」はそのカテゴリの根拠として使ったソース数。
- 「コース別情報」は、そのカテゴリで話題になる具体的なコース・エリアがある場合のみ書く。
  無理に埋めない。
- 引用（「ソース：」行）は必ず元ページ本文に実在する文章を使い、（出典タイトル、投稿日、URL）
  を添える。投稿日が確認できない場合は省略してよいが、URLは必須。
- 公式サイトを根拠にした場合は「ソース：」ではなく「現行構成確認：」のように出典種別を
  区別して書く（利用者評価と公式情報を混在させない）。
- 情報が不足しているカテゴリでは、無理に見出しを埋めず「確認できる利用者情報が
  不足している」と明記する。
