# article.md のフォーマットと文章ルール

対象は2種類あり、ファイル名が異なる。

- カテゴリ別: `<slug>/<category>/article.md`（例: `appi-kogen/advanced/article.md`）
- スキー場直下: `<slug>/full_article.md`（例: `appi-kogen/full_article.md`）

## カテゴリ別 article.md

```markdown
## 評価：◎/○/△

- **良い点：** 
- **気になる点：** 
- **コース：**
    - コース名：特徴を1〜2文、50〜100字で記述する。
```

### 評価基準

- **◎：** 質、量、バリエーション、回しやすさなど、複数の面で明確な強みがある
- **○：** 十分に楽しめるが、量、バリエーション、動線などに一部制約がある
- **△：** 対象要素が少ない、限定的、または利用しにくい

判定ルール:

- **情報不足だけを理由に評価を下げない。**
- ◎と○で迷ったら◎、○と△で迷ったら○にする。

### 良い点・気になる点の書き方

- スキー場全体における**そのカテゴリの特徴**を説明する。
- 個別コースを順番に紹介する書き方はしない。斜面の傾向、量、バリエーション、使いやすさ、
  利用者がどのように楽しめるかをまとめる。
- 具体的なコース名（固有名詞）を出さない。エリアの位置や特徴で言い換える
  （例:「〇〇コース」ではなく「山頂側の急斜面」のように書く）。コース名は「コース」欄にのみ書く。

### コース欄の書き方

- そのカテゴリで話題になる具体的なコースがある場合のみ、コース名ごとに特徴を1〜2文、
  **50〜100字で記述する。50字を下回ってはならない。**
- 1文で50字に届かない場合は、根拠に基づく具体性（斜度・幅・混雑傾向・向いている
  滑走スタイルなど）を1文足して2文構成にする。
- 作成後、各コース説明の文字数を数えて50〜100字の範囲に入っているか自己点検する。

## スキー場直下の full_article.md

`<slug>/full_article.md` に原則3段落で作成する。

1. **スキー場全体の性格と、向いている人**
2. **主な強み**
3. **主な気になる点**

- 7カテゴリの article.md / detail.md の内容を統合し、初めて訪れる読者にも
  全体像が分かる文章にする。
- 具体的なコース名は原則使わない。位置関係、エリア構成、斜面の傾向、
  利用者の動線で説明する。

## 文章ルール（両ファイル共通）

最重要: **そのスキー場に行ったことがない人が読んで、特徴・強み・弱みが理解でき、
スキー場選びに役立つこと** 読みやすさ・分かりやすさを最優先する。

守ること:

- `detail.md` にない情報を追加しない
- 引用やURLを載せない
- 外部レビューの文章をコピーしない（必ず自分の言葉で書き直す）
- 自然で分かりやすい「です・ます」調にする
- 一文に複数の情報を詰め込みすぎない
- 不自然で抽象的なAI表現を避ける（「〜と言えるでしょう」「魅力が満載」
  「幅広いニーズに応える」のような中身のない言い回しを使わない）
- 「圧雪」「非圧雪」「コブ」「バンク」「キッカー」「BOX」など一般的なスキー用語はそのまま使ってよい
- 悪い内容は必要以上に断定的に書かない（「〜という声があります」「〜場合があります」程度に留める）
- 判断できない内容を推測で埋めない
- 既存の `article.md` の文章には引っ張られず、`detail.md` から新しく作成する

## 自己点検チェックリスト

- [ ] コース説明が全て50〜100字である
- [ ] 良い点・気になる点の文中に「コース」欄に列挙した固有名詞が含まれていない
- [ ] スキー場直下 full_article.md が原則3段落である
- [ ] `detail.md` にない情報を追加していない
- [ ] 引用・URLを載せていない
