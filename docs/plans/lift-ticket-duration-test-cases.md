# リフト券・レンタル料金のテストケース（案）

料金計算で「1日」「1日＋ナイター」「ナイター」「N時間（1〜9）」と人数・レンタルを選んだとき、
どのスキー場でも整合した結果になるかを確かめるためのケース一覧。
リフト券とレンタルは、基本的に同じケースで同時に確認する。

## 前提

### データは調べたまま保存する

- データには公式に載っている券・レンタルだけを入れる。1日券が無い施設に、9時間券の料金で1日券を作らない。
- 営業時間が不明な施設は「不明」のまま保存する。8:00〜17:00 は計算のときだけ使う。
- ナイター営業がある施設は、通常営業とナイターの時刻を必ず持つ（推定でもよい）。データの検証で確認する（Z04）。
- テスト用の架空スキー場も、調べたままの形で作る。

### テストの構成

- 架空スキー場のケース（A〜YM）が主軸。料金は毎季変わるので、実在施設の料金を期待値にすると「仕様の不具合」と「データ更新」の区別がつかなくなる。
- 実在施設は、固定コピーしたフィクスチャ（X）と、期待値を書かない不変条件チェック（V）で補う。本番JSONの更新でテストが壊れない形にする。
- 架空ケースごとに元にした実在施設を「〜型」として書き、どの型にも当てはまらない実在施設は Y の警告で検出する。料金収集で新しい型が出たら、この文書に架空ケースを足す（スキルの完了報告に含める）。

### 計算の仕様

| No | 仕様 |
|---|---|
| S1 | 「1日」は1日券の最安。1日券が無ければ、いちばん長い時間券を出す（「9時間券 6,300円」のように、券名と金額だけ出す） |
| S2 | 1日券より安く、その日の営業をすべて含む券があれば、「1日」ではそちらを出す（例: 営業8時間の日の9時間券） |
| S3 | N時間はナイターも含めて数える。休止時間（16:30〜17:30の運休など）は滑れる時間に数えない |
| S4 | N時間の結果の並び: ①時間帯の決まっていない券（1日券・時間券）でN時間滑れる最安を一番上に出す。②「時間帯が決まっていてもよければ」として、午前券・午後券・ナイター券など時間帯が決まった券（その組み合わせを含む）で①より安いものを、利用時間付きで出す。時間帯の決まっていない券が無ければ、②の最安を一番上に出す |
| S5 | 「1時間短くてもよければ」として、N−1時間以上滑れて、一番上より安い券を出す。2時間以上短い券は出さない。「1日」でも、その日の営業より1時間以内しか短くならない券なら出す |
| S6 | 「1日＋ナイター」で2枚に分けないと足りないときは、1枚で滑れるいちばん長い券も候補に出す（めがひらの9時間券） |
| S7 | Nがその日に滑れる時間より長ければ、滑れる時間全体の結果を出し「この日の営業は8時間（8:30〜16:30）です」と注記する |
| S8 | 通常営業の時刻が不明なら 8:00〜17:00 と仮定して計算し、「営業時間不明のため8:00〜17:00と仮定」と注記する。ナイターはナイターの情報から計算し、仮定の終了はナイター開始までにする。ただし他の日に通常営業の時刻があり、その日はナイターだけが載っている日（川西小松の火・木・金）は、ナイターだけの日として仮定しない。「1日」もナイターの営業時間を指し、「この日はナイター営業のみです（18:00〜20:50）」と注記する |
| S8b | 「1日＋ナイター」を2枚まででも覆えない日（白銀台: 営業12時間・最長5時間券）は、2枚で滑れる時間がいちばん長い組み合わせを出し、S7と同じく営業時間を注記する（5時間券2枚）。3枚以上は組み合わせない |
| S9 | 時間券は、利用時間帯の制限が書かれていなければ、ナイターにも使える |
| S10 | 1枚で足りなければ2枚まで組み合わせる（1日券＋ナイター券、9時間券＋4時間券など） |
| S11 | 早朝営業は「1日」「N時間」に含めない |
| S12 | 定休日・営業期間外は、どの長さでも料金なし |
| S13 | 回数券・ポイント券・初心者エリア限定券は、長さの指定には使わない |
| S14 | 25時間券のような「シーズン中に時間を使い切る券」は、その人の全日程で滑る時間の合計で比べる（T） |
| S15 | 食事券・温泉付きなどの券も通常の券と同じに計算し、付いている物を券名の横に出す |
| S16 | Web・前売・早割の料金は、照会日に買えて窓口より安ければ、それを料金にする（「Web購入」と表示）。買えなければ窓口の料金にする。リフト券とレンタルで同じ |
| S17 | レンタルは1人1店舗で借りる。延長日・複数日の組み合わせも、同じ店舗・同じグレードの料金だけで作る |
| S18 | レンタルは、リフト券と同じ時間・日程に合う料金を使う。半日・時間・ナイターのレンタルは、時間帯が合うときだけ使う |
| S19 | 割引は1人1券に1つだけ。併用可否が不明（unknown）・併用不可（not_stackable）の割引は重ねず、安いほう1つを出す。公式に併用可と書かれた割引だけ重ねる（今は0件） |
| S20 | 会員・アプリ登録・宿泊者・クーポン・既存ICカードへのチャージなど、入力から判定できない資格が必要な割引は確定料金にせず、条件付き候補に出す（Q）。年度単位の生年月日範囲で決まる年齢割引（20才割など `nominal_age`）は、入力年齢が一致すれば適用し、生年月日範囲と必要書類を警告に出す |
| S21 | 有効時間が資料に無い券（`validity.mode: unknown`）は長さの計算に使わず、料金表にだけ出す。営業区分が不明でも時刻があればその時刻で計算する（NX06〜NX08） |
| S22 | レンタルが未収集（`rentals` が空）の施設でレンタル有りを選んだら、リフト券だけ計算して「レンタル料金の情報がありません」と出す。公式に無いと確認済みなら「レンタルはありません」 |
| S23 | レンタルの「1人1店舗」は人ごと。同じ人の中で店舗を混ぜない。人が違えば店舗が違ってよく、リフト券の購入経路とレンタルの経路も別々に選ぶ |
| S24 | 返金される保証金（ICカード保証料）は合計に入れず注記だけ出す。返金されない発行手数料・入場料は手数料として合計に入れる（W10・PB83・Y9） |
| S25 | 雪マジ（18〜22歳の入力）は YM の仕様 Y1〜Y15 に従う。雪マジで無料・割引になる券は、通常の割引（Web・前売・学割・こどもデー等）と比べて安いほうを一番上に出す |

## Y. 架空ケースに当てはまらないスキー場の警告

架空スキー場のデータも実在施設と同じ形式のJSONで作る。両方から同じ方法で「構造の特徴」を取り出し、実在施設にあって架空ケースに無い特徴を警告する。

実装はスキル `collect-ski-lift-ticket-pricing` 側にある（置き場所・形式は `references/fictional-fixtures.md`、特徴キーは `references/feature-catalog.md`）。
架空スキー場の本体は `tests/fixtures/fictional/<resort>.json`、行単位のケース（K01・W05・YM30 など）は `tests/fixtures/fictional/variants/<CASE_ID>.json` に「基準スキー場＋差分」で置く。
照合は `scripts/check-fictional-coverage.mjs`、確認済みの特徴は `references/coverage-acknowledged.json`。

機械で拾えるのは抽出関数が知っている軸の組み合わせだけ。抽出関数に無い新しい構造（`notes_ja` にだけ書かれた条件など）は、料金収集の完了報告で「架空ケースに無い型」として人・AIが報告し、文書と抽出関数の両方に足す。2回目からは機械で拾える。

### 取り出す特徴

| 分野 | 特徴の例 |

### 警告の出し方

- 特徴ごとに照合し、「恐羅漢: 期間限定の時間券が1日券より安い（架空ケースなし）」のように、施設名と足りない特徴を出す。
- 主要な組み合わせも照合する（営業時間の型×券の型、ナイターの型×1日券の有無、同行者ルール×レンタル）。全組み合わせは数が多すぎるので対象を決めておく。
- スキーマに無い値やフィールドが出てきたら、それも「新しい構造」として警告する。
- 料金収集スキルで料金JSONを保存したときに、その施設について警告を出す。
- CIでは全施設をまとめて照合する。警告が出たら、架空ケースを足すか、理由付きで「確認済み」の一覧に載せるまで失敗にする（警告を見落とさないため）。

| ID | 確認すること |
|---|---|
| Y01 | 架空スキー場の特徴を取り出す処理と、実在施設の特徴を取り出す処理が同じ関数である |
| Y02 | 架空ケースに無い特徴を持つ実在施設があれば、施設名と特徴名を出して失敗する |
| Y03 | 「確認済み」の一覧に理由付きで載っている特徴は失敗にしない。理由が空なら失敗にする |
| Y04 | スキーマに無い値（新しい利用単位など）を持つ施設があれば警告する |
| Y05 | 架空スキー場から特徴を1つ消すと、その特徴を持つ実在施設が警告に出る（チェック自体のテスト） |
