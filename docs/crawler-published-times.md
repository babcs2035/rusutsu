# クローラーの更新日時

コース・リフト・コンディションの更新日時は、全稼働クローラーが通る
`persistLatestResult` で `updateTime` に正規化する。個別クローラーは従来どおり
公式の対象項目に掲載された文言を `update` に入れる。取得元・取得項目は増やさない。
`update` は互換性と照合のため残す。旧形式の項目内 `time` も読み取るが、
トップレベルの取得日時 `time` は更新日時の補完に使わない。

```json
{
  "update": "3月29日 午前8時現在",
  "updateTime": {
    "raw": "3月29日 午前8時現在",
    "year": null,
    "month": 3,
    "day": 29,
    "hour": 8,
    "minute": null,
    "second": null,
    "precision": "hour",
    "timeZone": "Asia/Tokyo"
  }
}
```

- 年月日、年なしの月日、時刻だけ、日・時・分・秒の精度を保持する。
  記載のない成分は `null` のままとし、現在年・当日・00:00などで埋めない。
- 全角、和文・区切り記号付きの日付、曜日、午前午後、AM/PM、
  オフセット付きISO日時を共通パーサーで扱う。明示されたオフセットは日本時間に変換する。
- 欠損・ハイフン・「現在」「更新」だけなら `updateTime: null`。
  非空だが曖昧・不正・未対応の文言は `raw` を残し、全成分と `precision` を `null` にする。
  複数カテゴリの日時が混在した文章から、先頭の日時だけを採用しない。
- ローカルJSONとリモートAPIのカテゴリデータに同じ構造を付ける。
  HTTP送信では既存の秘匿化・文字数制限後の `update` に合わせて再計算する。
  APIは受け取った `updateTime` と `update` の一致を検証する。

画面も同じパーサーを使うため、既存JSONを書き換えずに新しい表示を使える。
新規取得結果には次回の保存から `updateTime` が付く。
API契約は旧クライアントの `updateTime` なしの送信も受け付ける。
APIとワーカーを別々に配備する場合は、追加フィールドを受け付けるAPIを先に配備する。

一覧の出典欄はURLと日時を添字で対応させない。出典リンクは登録された件数だけ表示し、
項目ごとの日時は最古から最新の範囲にまとめる。これは各項目の更新日時の幅であり、
期間中ずっと同じ営業状況だったことを示すものではない。

- 複数日: `2026/3/29〜4/4現在`
- 同日: `2026/4/4 08:00〜17:30現在`
- 時刻だけ: `08:00〜09:30現在`
- 年付き・年なし・日付なしは別々に集約する。年不明の年またぎは範囲にしない。
- 精度が混在するときは共通する粗い精度でまとめ、個別のコンディション等では
  元の精度で表示する。認識できない日時に「現在」を付けない。

保存済みデータの読み取り専用監査:

```sh
node --import tsx src/private/scripts/crawl_latest/audit-published-times.ts
```

最新保存ファイルをスキー場ごとに1件ずつ読み、結果を
`src/private/data/resorts-temporary/tmp/published-times/audit.json` に保存する。
サイトへのアクセスや、既存の保存データ・本番APIの更新は行わない。
未対応の文言はレポートで確認し、意味が確定するものだけ共通パーサーとテストに追加する。
