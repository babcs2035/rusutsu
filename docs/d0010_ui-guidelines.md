# UI 指針 (スキー場詳細・スマホを中心に)

画面を作る・直すときに守ること．迷ったら「スマホで地図と中身がどれだけ見えるか」を優先する．

## 0. 既存画面との統一と，提出前の確認

新しい機能は，同じ画面に以前からある機能の一部として作る．デザインの統一と画面構成のコピーを混同せず，ヘッダーの有無は操作の意味とユーザーの指定に合わせる．実装前に参照する画面とコンポーネントを確認し，作業中も比較する．独自の画面構成や装飾を先に作り，あとから既存画面へ近づける進め方をしない．

| 用途                                                         | 使う既存実装                                                                                                 |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| PC のスキー場詳細ヘッダー・名前・所在地・お気に入り・比較・× | `resort-detail/components/InfoSection.tsx`                                                                   |
| スマホの詳細ヘッダー                                         | `home/layout/HomeLayout.tsx` の `MobileContextHeader`．本文側に重複したヘッダーや×を足さない                 |
| パネル・タブ                                                 | `AnimatedPanel`，`DetailTabs`／`UnderlineTabs`．既存の幅と高さを保つ                                         |
| 読み込み中                                                   | `shared/components/LoadingSpinner.tsx`．その画面で必要な閉じる操作と配置を保ち，本文の領域内に表示する       |
| 操作・入力・選択欄                                           | `components/ui` の `Button`，`Input`，`Textarea`，`Select`．同じ用途の操作の大きさ・variant を揃える         |
| スキー場の地図                                               | 既存の `DynamicMap`／`MapLibreResortMap`／`ResortFinalizedMap`．機能ごとの別レンダラーや別の線・色を作らない |

スキー場詳細から投稿を始めるときは，PC では地図を維持し右パネルを切り替える．現地レポート中は PC・スマホともスキー場ヘッダーを非表示にする．投稿画面右上には既存と同じ見た目の×を置き，押すと投稿を閉じて元の詳細へ戻す．終了操作に独自の説明や別名ボタンを足さない．項目の場所を選ぶポップアップも同じ地図描画・難易度／斜度・タイルを使う．読み込みや入力ステップの変更を理由にヘッダーや×を作り直さない．

提出前には，通常の詳細と変更した画面を実際に開いて比較する．PC・375px スマホの画像を確認し，狭い詳細パネル 346px，通常幅 500px，ポップアップ 320px も該当箇所で確認する．次を実測・操作し，問題があれば修正して再確認する．

- 読み込み中・失敗・空・入力中・確認・完了で，ヘッダーと×の位置，パネル幅が揃う．
- 文字・ボタン・凡例が重ならず，不要な横スクロールやボタンの折り返しがない．フォームの最後まで縦スクロールできる．
- 同じ用途のボタンの形・色・高さ，見出し・本文の文字サイズと余白が既存画面と揃う．
- クリックで操作するボタン・リンク・メニュー項目には共通の `cursor: pointer` を使う．無効な操作，文字入力，ドラッグでは各操作に合ったカーソルを維持する．
- 閉じる／戻る／入力ステップ変更で，地図の表示と入力内容を仕様どおり保持する．

型チェック・lint・DOM 上の存在確認は，画像での見た目確認の代わりにならない．Luna が実装した場合も親が最終確認する．確認用画像とログは `src/private/data/resorts-temporary/` 配下に置く．ツールの制約で確認できなかった操作は，検証済みと区別して報告する．

## 1. スマホは縦の余白を最優先で守る

- 縦の場所を取る要素は，毎回「これは本当に1段必要か」を確認する．ボタンは見出しや名前と同じ行に並べ，ボタンだけの行を作らない．
- ヘッダー・タブ・ツールバーの高さの目安:
  - 詳細ヘッダー (名前＋所在地＋操作ボタン): ボタンは 1 行に横並び．2 段に積まない．
  - タブ (`ゲレンデ`/`料金`/`天気`/`リンク集`/`投稿`): `UnderlineTabs` の `compact` (スマホ `h-9`，PC `h-10`) を使う．
  - 操作ボタン: スマホは `h-8` まで．見出しの横に添えるボタン (説明・詳細) は `h-6` 前後 (`DetailButton compact`，`StatusLegendDialog compact`)．
- 文言の長いボタンは短くし，正式な操作名は `aria-label` に持たせる (例: 表示は「比較」，aria-label は「比較に追加」)．
- 2 つの要素が狭い幅でも収まるなら横に並べる (例: コースとリフトの集計は `grid-cols-2`)．1 列あたり約 170px (375px 幅の端末) に収まるように文字と記号の大きさを決める．
- 余白 (`py-*`/`gap-*`/`mt-*`) は小さめから始める．補足も 15px 以上にし，本文との違いは主に太さと配色で示す．
- ボタン・チップ・バッジの文字は絶対に折り返さない (`whitespace-nowrap`)．「詳\n細」のように縦に割れたら列幅か配置が間違っている．表の中のボタン列は，ボタンが 1 行で収まる幅を確保する．
- スキー場詳細の天気タブ「リンク一覧」は，4 サイト (Snow Forecast・tenki.jp・ウェザーニュース・Windy) のリンクがそれぞれ 1 件ずつの場合，スマホでも横 1 列に収める．狭い枠では表示名と余白を詰め，支援技術には正式名を伝える．同じサイトに複数地点などの項目がある場合は折り返してよい．320px・375px のスマホと幅 346px・500px の PC 詳細パネルで確認する．
- 「詳細」ボタンはどこでも `DetailButton` を使う．表の行や見出しの横では `compact`．独自の青いリンク文字などで代用しない．

## 2. 置かないもの

- ログイン／アカウントのボタンはホームの検索画面だけに置く．詳細・比較画面 (PC・スマホとも) には表示しない．
- お気に入りはハートとピンク，比較は青に統一する．ホームの検索欄の右に「♥ お気に入り」 (`SavedCompareButton`，`rounded-md`・太字・影付き) を置く．保存した比較リストが無ければ押すとそのままお気に入りの比較を開き，あればお気に入りと比較リストの一覧のダイアログを開く．お気に入りが 2 件未満で比較リストだけあるときは「比較リスト ›」にする．幅が狭い画面では，検索欄の幅を保つためにログインやお気に入りをアイコンで表示する．ホームのアカウント画像は直径 32px，外枠なしで表示する．
- 画面の下に浮かせる操作は `FloatingActions` にまとめ，左下を「N 件を比較 ×」 (`CompareTray`．1 件以上選んだときだけ出し，×で選択を消す前に確認する)，右下をその画面の操作にする．右下はスマホのホームが「リスト N 件／地図」 (`ViewToggleButton`)，詳細がスマホ・PC とも「＋比較／✓比較中」 (`CompareAddButton`)．詳細のヘッダーには「比較」を置かない．押す前の「＋比較」は青の塗りで目立たせ，押した後は白抜きにする．PC は一覧パネル・詳細パネルの下端に同じ並びで出す．投稿・修正の入力中，コースやリフトを選んでいる間，地図を広げている間は出さない．浮かせるボタンの下に最後の行が隠れないよう，一覧と詳細のスクロール領域の下に 4.5rem の余白を足す (詳細は `--floating-actions-space`)．検索結果の件数は，スマホの地図では「リスト N 件」のボタン，リストと PC では並び替えの右に出す．
- 通常の比較画面の見出し行には，×の左に「リストに保存」 (スマホは `ListPlus` アイコンのみ) を置く．既存リストへの追加か，新しいリストの作成を選べる．お気に入り比較ではヘッダーのハートと保存ボタンを出さず，概要カードの詳細の左にだけお気に入りのハートを置く．通常の比較と保存済みリストのカードにはハートを出さない．保存済みリストとお気に入り比較では「≡ 編集」ボタンを置く (PC はヘッダーの×の左，スマホは概要・料金タブの「11/19 大人 1 名」の行の右端だけ．部品は `ResortListEditButton`)．カードに解除ボタンは置かない．編集はモーダルで，リスト名 (お気に入りは名前固定なので出さない)・「一覧 N 件 ＋追加 ⣿で並び替え」・左につまみ，右にゴミ箱の付いた一覧を並べ，名前の変更・削除・追加・並び替えはその場で保存する (削除は確認を出す)．並び替えはつまみのドラッグか上下キーで行い，比較画面のカードもその順に並ぶ (並べ替え・削除だけなら読み込み中に戻さない)．保存済みリスト・お気に入り比較から開いた詳細には「比較」ボタンを出さない．お気に入り比較から開いた詳細はハートも出さない (保存済みリストから開いた詳細のハートは出す)．手で選んだ比較から開いた詳細と通常の詳細は，ハートと「比較」の両方を出す．「＋追加」とその「検索条件」は同じモーダル内に重ねる画面にし，通常の検索と同じ判定・条件部品 (`FilterConditionFields`，料金計算は除く) を使う．どの画面も右上は `PanelCloseButton` の×だけにし，×・Esc・外側のタップで 1 段ずつ戻る．PC ではリスト名を件数の左に出す．件数は読み込み中も比較対象の数を出す．最後のスキー場を外しても空のリストを保持し，追加できるようにする．
- 同じ情報や同じ操作を 2 か所に置かない．
- 値だけで意味が分かるものに「レベル」「圧雪」「営業状況」のようなラベルを付けない．値をチップにして横に並べる．
- 「日時不明」「コメントはありません」など，無いことを知らせるだけの文言は出さない．無ければ何も書かない (未取得を区別したいときだけ `NotFetchedBadge`)．
- 1 画面に収まる量の情報をタブで分けない．重要度順に縦に並べる．

## 3. 情報の並べ方

- 見出し行に「名前・件数・説明(ⓘ)・詳細(›)」をまとめ，その下に中身，出典は最後に小さく添える (`SourceLine compact`)．
- 数字が主役のところは数字を大きく，記号 (○△×) は数字より小さくする (`StatusMark size="sm"`)．
- 営業状況は一覧と同じ ○△× の記号＋「全面滑走可／一部滑走可／クローズ」の文言で書き，色付きの枠で一番目立たせる．
- 1 行に横の余白が残るなら，出典や動画リンクなどの補足をその右に寄せて置き，行を増やさない．
- 別のスキー場名を並べるときは地図のラベルと同じ省略名 (`getResortLabelName`) を使う．
- ホームの並び替えボタンとメニューは同じ文字サイズ・太さに揃える．「都道府県別」を選んだら，初期表示は地方だけにし，地方 → 都道府県 → スキー場の順に展開する．都道府県名の横の件数は，絞り込み後の検索結果だけを数える．
- ホーム一覧の初期の並びは「都道府県別」で，県内は滑走距離が長い順 (大きいスキー場から)．並び替えメニューの「都道府県別」の行の右に「滑走距離｜名前順」の切り替えを置き，ボタンには「都道府県・滑走距離」「都道府県・名前順」と出す．「距離順」のように何の距離か分からない書き方をしない．
- 「名前順」と県内の名前順は，ふりがな (`reading`) の五十音順．英字で始まる名前は先頭に並んでよい．
- 滑走距離は保存済み集計 (`ski_resort_operation_summaries` の `courseDistanceTotal`／`courseDistanceOpen`) を使い，詳細の「滑走距離」と同じ計算 (`src/shared/course-lift/courseDistance.ts`) にする．標高未取得で斜面距離が無い線は水平距離で代える．地図のコースが無いスキー場は後ろに回し，名前順で並べる．
- 一覧カードには通常，滑走距離を出さない．「滑走可能距離が長い順」のときだけ，コースの欄はラベル「コース」のまま，値を「滑走可能距離/総滑走距離km」に替える．10km 以上は整数 (39/40km)，未満は小数 1 桁 (4.5/9.8km)．このときだけコース列を「128/150km」が入る幅 (7.25rem) にし，リフト列は中身の幅，残りを料金にする．
- 一覧カードの料金欄は「営業期間外」を「期間外」と短く書く (比較画面などは「営業期間外」のまま)．
- 都道府県別の見出しは地方・都道府県とも `text-sm` 太字で，文字の大きさではなく形で階層を分ける．地方は灰色の帯 (36px) で，開閉しても色を変えない．都道府県は左に青い縦線のある行 (32px) で，開いた都道府県だけ線を濃い青，背景を一覧カードの数値帯 (`sky-50`) より濃い青 (`sky-200`) にして見分けられるようにし，その線をスキー場の並びの下まで続ける．スクロール中は地方と都道府県を一覧の上端から 2 段で固定する．
- 一覧カードは「スキー場名 → 旧称 → 都道府県・市区町村」の順に並べる．固定部分の上に余白を残さず，角丸部分も不透明な背景で覆って背後のカードを見せない．

### ホームの検索条件 (エリア・料金・絞り込み)

- 条件は検索欄の下の 3 つのチップ「エリア」「料金 (日付と人数)」「絞り込み」に分ける (`SearchConditionBar`)．チップには選んだ内容をそのまま出す (例: 「長野・新潟」「11/22 大人 2 名 〜¥9,000」「絞り込み 2」)．何も変えていないあいだは「エリア」「日付・人数」「絞り込み」とだけ出し，一覧の料金は今日・大人 1 人・1 日券で出す．検索欄は名前の入力だけに使う．
- チップは地図の上でも白い一覧の上でも埋もれないよう黒で塗り，条件を選んだチップだけ青にする．航空写真の上では，選んでいないチップと「リスト」のボタンを白にする．
- チップを押すと，すぐ下にその条件だけのモーダルを開く．中で変えた条件はその場で一覧・地図・件数に反映し，「○件を表示」「適用」のボタンは置かない．見出しに件数と「条件をクリア」 (そのモーダルの条件だけ戻す) と×を置き，×・Esc・外側を押して閉じる．閉じたときに条件が変わっていれば地図を結果に寄せる．
- エリアは全部の県を 1 画面に並べ，押すだけで複数選べるようにする．左の地方名のボタンに「全選択／解除」を添え，その地方をまとめて選ぶ．
- 料金のモーダルは `TicketPartyEditor` (利用日・滑る長さ・区分・年齢・人数・レンタル) と予算 (合計の上限，入力欄) にする．「日を追加」「利用者を追加」は見出しの右の小さい枠のボタン，人数は −／＋ (行が 2 つ以上あるときは，1 人から減らすとその行を消す)，レンタルは 1 つの欄にして押すと小窓で「なし／スキー／スノーボード」と用具を選ぶ (行の下に段を足さない)．予算は料金の計算結果で絞り，料金が出ないスキー場は外す．
- 絞り込みの規模 (滑走距離・標高差・コース数・リフト数) と山麓・山頂の標高は，数字の入力欄だけにする．選択肢のボタンは置かない．
- 一覧の料金欄の名前は，条件が「大人 1 人・1 日券・レンタルなし」のあいだは「大人 1 日料金」，変えたら「合計料金」にする (`priceColumnLabel`)．名前が長いので，料金の列をコース・リフトの列より広く取る．
- 地図のスキー場名のラベルは，料金の条件 (日付・人・年齢・レンタル・予算) を変えているあいだだけ，名前の後ろに青で料金を添える．初期のままなら名前だけ．
- 画面に薄く小さい説明文・注記を足さない．任意の入力は欄の中に薄く「任意」と書くだけにする．
- スマホのホームの地図では，ホーム (地図をリセット) と地図の種類 (標準／航空写真) を現在地ボタンの下に同じ大きさで縦に並べる．左下は「N 件を比較」が出る場所なので空けておく．

### リンク集のタブ (スキー場のリンク一覧)

- グループと種類の並び順は全スキー場で同じにする (定義は `src/features/resort-links/linkTypes.json`)．リンクの無い種類・グループは出さず，順番だけを固定する．
- グループ名は小見出し (`text-sm` 太字)．その下に，種類名そのもののボタン (例:「コース営業状況」「リフト営業状況」「Googleマップ」) を横に並べて折り返す．押すとそのページを別タブで開く．「公式」「開く」だけのボタンを種類名の横に並べる形にしない．
- ボタンは天気タブのリンクと同じ角丸の四角にする (`rounded-md`，`text-xs`，`px-2.5 py-1.5`)．文字色と末尾のアイコンは共通の外部リンクに揃える．
- 1 ページ＝1 ボタン．同じ種類で同じページ (`#…` の位置違いを含む) を指すリンクは 1 つにまとめ，出発地・節ごとにボタンを増やさない．公式サイトは同じドメインで 1 つ (別ドメインの共同サイトだけ 2 つ目にする)．
- 同じ種類に別々の公式ページが 2〜3 件あるときは，種類名に区別の名前か番号を添えたボタンにする (「レンタル（予約）」「ゲレンデマップ 2」)．1 件のときの地点名・補足はボタンの `title` に持たせる．
- レンタルは料金の「レンタル」1 つにまとめる (リフト券データのレンタル料金と公式のレンタル店のページ．施設には出さない)．
- バスツアーは「車」「公共交通」と同じグループの小見出しにし，その下にツアー会社名のボタンを 1 社 1 つ並べる (そのサイトのスキー場ページ．無ければスキーツアーのトップ)．出発地のチップや，種類名の固定幅の列は使わない．公式ページが案内するツアー会社のリンクも，同じ会社のボタンにまとめる (クローラーが取ったスキー場ページを優先)．例外はラド観光だけで，出発地に依らないページが無いため地方ごと (「ラド観光（関西発）」など，最大 5 件) に出す．
- それ以外で 4 件以上ある種類は，ボタンの下に「種類名（左・固定幅・`text-xs`）＋リンクのチップ（右・折り返し可）」の行でまとめる．
- サイト外へのリンクは必ず別タブで開く (`ExternalLinkComponent`．自前で書けない地図の著作権表示などはルートの `ExternalLinksInNewTab` が補う)．
- 天気のリンクは天気タブにもあるが，リンク集のタブは「全部のリンクが同じ場所にある」ことが目的なので重複を許す．出すのは天気タブと同じリンク (同じ地点) だけで，旧データにある全地点へ増やさない．
- SNS はリンク集の「SNS」グループに並べる (SNS 専用のタブ・埋め込みは置かない)．X・Instagram・Facebook のボタンには `public/social` のロゴを種類名の前に添える．

### 雪マジ・EV 充電のチップと，スキー場比較のリンク集

- 絞り込みのオン・オフは「雪マジ → NSDキッズ → マックアース → スノーバーズ → EV充電」の順に `FilterToggle` で並べる (サービスの定義は `src/shared/passPrograms.ts`)．外部サービスのボタンには右に ↗ の小ボタン (`link`) を付け，そのサービスのサイトを別タブで開く．並びは 3 列で，枠が 20rem 未満 (幅 320px のスマホ) のときだけ 6 文字の名前が切れないよう 2 列にする．

- 「雪マジ」「EV充電」は `ResortFeatureChips` を使う．詳細ヘッダーでは所在地のすぐ後ろ，比較の概要カードでは営業状況の右側に縦並びで置く．押せると分かるよう枠と「›」を付け，押すとモーダルで中身を出す．PC の詳細では，モーダルを詳細パネルの範囲の中だけに出し，地図の上に重ねない．
- 比較の概要カードはコース・リフトと出典だけを左側の枠に入れ，チップはその枠の外の右側に縦並びで配置する．営業状況の囲い・背景にチップまで含めない．カード幅は約 350px (1440px 前後の画面の 4 列・スマホ) を想定し，狭い幅でもコース・リフトの件数と出典を表示する．
- 比較の「リンク集」は，詳細のリンク集と同じ部品 (`LinkGroups`／`LinkGroupBody`) と同じ並び順で出す．
  - スマホはゲレンデと同じ 1 画面 1 スキー場の横スワイプ (`CompareCarousel` の送りボタンと点)．スキー場名の行は残し，カードの中だけを縦に送る．
  - PC はグループ (基本・ゲレンデ・料金…) を行，スキー場を列にした表．スキー場名の行とグループ名の列を固定し，縦横ともタブの枠の中で送る．比較中のどこにもリンクが無いグループの行は出さず，リンクの無いマスは空のままにする．1 列は 20〜36rem．

## 4. 文字サイズと配色

PC とスマホの最小文字サイズは 15px とする．地図の注記，グラフの軸，表の補足，通知にも適用する．狭い枠では，余白を詰めるか，内容を折り返せるようにする．

| 役割                      | スマホ           | PC (`md:`)       | 例                                                          |
| ------------------------- | ---------------- | ---------------- | ----------------------------------------------------------- |
| セクション見出し          | `text-base`      | `text-base`      | 営業状況，ゲレンデマップ                                    |
| 小見出し                  | `text-sm`        | `text-sm`        | コース，リフト，コンディション，コメント                    |
| 主役の数字                | `text-base` 太字 | `text-base` 太字 | ○△× の件数                                                  |
| 値・本文                  | `text-base`      | `text-base`      | コメント本文，入力欄                                        |
| 補足                      | `text-xs` (15px) | `text-xs` (15px) | 表の列見出し，件数の単位，出典，取得日時，`NotFetchedBadge` |
| タブ                      | `text-sm` (15px) | `text-sm` (15px) | ゲレンデ／料金／天気／リンク集／投稿                        |
| スキー場名 (詳細ヘッダー) | `text-lg`        | `text-lg`        | 詳細の先頭                                                  |
| スキー場名 (一覧カード)   | `text-base`      | `text-base`      | ホーム一覧．ふりがなは出さず，詳細だけに出す                |

- PC でもスマホと同じ段階を使い，`md:` で文字を大きくしない．PC は文字を大きくするより，地図を広く取り，一覧で多くの件数を見せる．テスラ車載ブラウザ (幅約 1000px) でも同じ．
- 詳細パネルと一覧パネルは PC で約 360px まで縮む．狭い側はスマホと同じ密度で収め，文字は上の段階から下げない．
- 一覧カードの値 (コース・リフト・料金) は，値があるときだけ青で目立たせ，「不明」を含む値はグレーの細字にする．
- 通常の操作は共通の `Button` を使い，主要な操作と選択中の状態には `primary` を使う．面・枠線・補足・エラーは `background`，`border`，`muted-foreground`，`destructive` などのテーマ変数を使う．地図の難易度・営業状態など，色で値や状態を表す箇所は対応する凡例と揃える．
- 本文は 400，補助ラベルは 500，操作ラベルは 600，主見出しは 700 を基本とする．ルビは親文字より小さくし，12px を目安にする（最小文字サイズの 15px はルビには適用しない）．
- 外部リンクは `ExternalLinkComponent` を使い，`primary` の青とリンク末尾の外部リンクアイコンを揃える．下線やツールチップは用途に合わせる．
- データを表で見せるときは共通の `Table` を使う．外枠とセルの境界には `border` の色を使い，幅に収まらない列は表の中で横にスクロールできるようにする．
- 変えたら，スマホ (375px) と PC の両方で実際の `font-size` を測って，上の表とずれていないか確かめる．

### フォント

使うフォントは全て Google Fonts から読み込む（`layout.tsx` の 1 リンクに集約）．この 3 種以外（システムフォントを含む）は使わない．

| フォント            | 用途                                                                     |
| ------------------- | ------------------------------------------------------------------------ |
| Murecho             | 本文フォント（`font-sans`・`font-body` の既定）と，地図のコース名・リフト名・スキー場名・縮尺 |
| Zen Kaku Gothic New | `font-heading` を使う見出しと共通のカード・ダイアログの題名              |
| Barlow              | `font-mono` を使う料金・数値・ID・座標・コードと診断ログ                 |

Murecho と Zen Kaku Gothic New は日本語の字形を持つため，日本語もこれらで描く．最終的なフォールバックは `sans-serif` のみである．共有画像の出典など，サーバー側（sharp）で生成する文字には Web フォントが使えないため既定のサンセリフを使う．

## 5. PC の詳細パネル

- 右パネルの幅は `--desktop-detail-panel-width` (`src/app/globals.css`)= `clamp(360px, 36vw, 480px)`，一覧パネルは `--desktop-search-panel-width` = `clamp(360px, 34vw, 440px)`．地図を画面の 6 割以上に保つための幅．
- 料金タブの公式リフト料金表 (5 列) は幅 450px 以上で横スクロールなしに収まる．それより狭いパネルでは表の横スクロールで全列を読めるようにする．幅を変えたら，一覧カードの「料金 営業期間外」が切れないことと料金表を確認する．
- パネルの中身は基本的にスマホ幅で組んだものを使う．PC だからといってこれ以上幅を広げない．
- 詳細の 5 タブ (ゲレンデ／料金／天気／リンク集／投稿) は `UnderlineTabs` の `fit` で均等に収め，横スクロールの先に隠さない．タブ高さはスマホ 36px・PC40px を維持する．幅 320px では「ゲレンデ」が枠いっぱいになるので，これ以上タブを足すときは名前を短くする．
- 料金表の列余白は `price-table` コンテナで決める．ルスツの 5 列は詳細幅 450px でも収まる．それより狭い場合は文字を過度に縮小せず，表の横スクロールで全列を読めるようにする．

## 6. 高さを変えたときの連動箇所

- `UnderlineTabs` の高さを変えたら，その下に貼り付く sticky の `top-*` (例: `src/features/resort-detail/tabs/OverviewTab.tsx` の「戻る」帯) も合わせる．
- モバイル検索ヘッダーの高さは `MOBILE_SEARCH_TOP_BAR_HEIGHT` を共有する．その下に条件チップの行 (40px，`MOBILE_CONDITION_BAR_HEIGHT`) を常に置く．地図はヘッダーの背後まで描画し，初期位置・検索結果の表示位置では `data-map-top-controls` の高さを避ける．リストだけはヘッダーと条件チップの行の高さを上の余白に取り，その下に並び替えと件数を並べる．

## 6. コース・リフトの詳細と地図

- スマホのコース詳細は，地図と両方の内容が同時に収まらないため「断面図／斜度の近いコース」のタブで切り替える．名前・営業状況・数値は共通で残し，初期表示とコース選択変更後は断面図を開く．タブは高さ 36px でスクロール中も残し，斜度の近いコースは取得できた表示件数を添える．コメント・紹介・メディアはタブ内容の下に置く．斜度の近いコースの表示条件を満たさない場合はタブを出さず，PC は従来の縦並びとする．候補の範囲「お気に入り｜全体」の切り替えは，PC では見出し「斜度の近いコース」の右，スマホではタブ内の「〇〇から」の説明と同じ行の右端に置き，切り替えだけの行を作らない．お気に入りが無いときは切り替えを出さず「全スキー場から」と書く．
- 名前の横にレベル・圧雪 (リフトは種別・速度) のチップを並べる．長い名前は折り返し，チップは名前に続ける．最長クラス (例: かぐら「X4 かぐら第1高速リフト～田代第1高速リフト連絡」) でスマホ幅を確認する．
- 閉じる (×) ボタンは共通部品で揃える。パネル・比較画面のヘッダーは `PanelCloseButton`，モーダル (ダイアログ) は `DialogCloseButton` を使う。見た目は両者とも `size-8` の丸型・X アイコン 16px・`text-slate-500`・hover で `bg-slate-100`（地図表示設定のモーダルの×が基準）。個別にクラスを書かない。
- モーダル (ダイアログ) は `shared/components/Modal` で統一する。背景は暗くせず，ややブラー (`DialogOverlay`：`bg-white/20 backdrop-blur-xs`) で手前をぼかす。外側クリック，Esc，閉じるボタン (必ず表示) のいずれでも閉じる。本体は白カード (`rounded-xl`，border，shadow，最大高さ 85dvh，超高い場合は内部スクロール) で，幅・余白は `className` で上書きできる (例: `max-w-sm p-5`)。トリガー付きは `trigger` にボタンを渡し，制御式は `open`／`onOpenChange` を渡す。詳細パネル内に制約して出す特殊なモーダル (雪マジ・EV充電) は個別実装だが，`DialogCloseButton` と `DialogOverlay` は共通にする。
- 何かを選択したとき，ほかのコース・リフトは「沈めるが消さない」．コースは形が読める濃さの灰色＋白縁で残す (`finalizedLayers.ts` の `DIMMED_STYLE`)．コースを選んでいるときのリフトは沈めず，ふだんどおり色と流れる動きで出す．リフトを選んだときのほかのリフトは紺で沈めるが，流れは止めない．
- コース比較の地図は斜度モードで，スキー場全体のコース・リフトを出し，比較するコースに寄せた状態から始める．ほかの名前は選択中の線に重ならない位置にだけ薄く出す (`showContextLabels`)．
- コース比較の地図は `embedded`：現在地は出さず，表示位置も保存しない (前の比較の位置を引き継がない)．拡大・縮小と方位のボタンは小さい版を使い，寄せる動きは出さない．評価基準などのタブを切り替えても地図をアンマウントしない (`keepMounted`)．読み込み中の枠は地図と同じ高さにして，表示が跳ねないようにする．
- PC のコース比較は，上の段に 2 コースの名前と地図を左右半分ずつの幅で並べ，下の段に「左の断面図｜数値の縦の表（左の値｜項目｜右の値）｜右の断面図」を置く．MacBook の画面でスクロールせずに収まる大きさにする (地図 `md:h-64`，断面図は `maxPlotHeight` で高さを抑える)．名前は 15px 以上で表示し，長い場合は折り返す．PC は断面図をなぞると同じコースの地図に点と斜度・標高を出し，断面図の上の読み値 (斜度・標高・水平距離) は出さない．スマホはタブを「地図／断面図／評価基準」の 3 つにし，2 コースを縦に積む．スマホでは比較表を出さず，断面図タブでいつもの横並びの数値 (`FeatureMetrics`) を各断面図の上に出す．「選択中」「斜度の近いコース」のような区別のラベルは付けない．
