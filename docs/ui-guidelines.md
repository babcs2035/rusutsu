# UI 指針（スキー場詳細・スマホを中心に）

画面を作る・直すときに守ること。迷ったら「スマホで地図と中身がどれだけ見えるか」を優先する。

## 0. 既存画面との統一と、提出前の確認

新しい機能は、同じ画面に以前からある機能の一部として作る。デザインの統一と画面構成のコピーを混同せず、ヘッダーの有無は操作の意味とユーザーの指定に合わせる。実装前に参照する画面とコンポーネントを確認し、作業中も比較する。独自の画面構成や装飾を先に作り、あとから既存画面へ近づける進め方をしない。

| 用途 | 使う既存実装 |
| --- | --- |
| PCのスキー場詳細ヘッダー・名前・所在地・お気に入り・比較・× | `resort-detail/components/InfoSection.tsx` |
| スマホの詳細ヘッダー | `home/layout/HomeLayout.tsx` の `MobileContextHeader`。本文側に重複したヘッダーや×を足さない |
| パネル・タブ | `AnimatedPanel`、`DetailTabs`／`UnderlineTabs`。既存の幅と高さを保つ |
| 読み込み中 | `shared/components/LoadingSpinner.tsx`。その画面で必要な閉じる操作と配置を保ち、本文の領域内に表示する |
| 操作・入力・選択欄 | `components/ui` の `Button`、`Input`、`Textarea`、`Select`。同じ用途の操作の大きさ・variantを揃える |
| スキー場の地図 | 既存の `DynamicMap`／`MapLibreResortMap`／`ResortFinalizedMap`。機能ごとの別レンダラーや別の線・色を作らない |

スキー場詳細から投稿を始めるときは、PCでは地図を維持し右パネルを切り替える。現地レポート中はPC・スマホともスキー場ヘッダーを非表示にする。投稿画面右上には既存と同じ見た目の×を置き、押すと投稿を閉じて元の詳細へ戻す。終了操作に独自の説明や別名ボタンを足さない。項目の場所を選ぶポップアップも同じ地図描画・難易度／斜度・タイルを使う。読み込みや入力ステップの変更を理由にヘッダーや×を作り直さない。

提出前には、通常の詳細と変更した画面を実際に開いて比較する。PC・375pxスマホの画像を確認し、狭い詳細パネル346px、通常幅500px、ポップアップ320pxも該当箇所で確認する。次を実測・操作し、問題があれば修正して再確認する。

- 読み込み中・失敗・空・入力中・確認・完了で、ヘッダーと×の位置、パネル幅が揃う。
- 文字・ボタン・凡例が重ならず、不要な横スクロールやボタンの折り返しがない。フォームの最後まで縦スクロールできる。
- 同じ用途のボタンの形・色・高さ、見出し・本文の文字サイズと余白が既存画面と揃う。
- 閉じる／戻る／入力ステップ変更で、地図の表示と入力内容を仕様どおり保持する。

型チェック・lint・DOM上の存在確認は、画像での見た目確認の代わりにならない。Lunaが実装した場合も親が最終確認する。確認用画像とログは `src/private/data/resorts-temporary/` 配下に置く。ツールの制約で確認できなかった操作は、検証済みと区別して報告する。

## 1. スマホは縦の余白を最優先で守る

- 縦の場所を取る要素は、毎回「これは本当に1段必要か」を確認する。ボタンは見出しや名前と同じ行に並べ、ボタンだけの行を作らない。
- ヘッダー・タブ・ツールバーの高さの目安:
  - 詳細ヘッダー（名前＋所在地＋操作ボタン）: ボタンは1行に横並び。2段に積まない。
  - タブ（`ゲレンデ`/`料金`/`天気`/`リンク集`/`投稿`）: `UnderlineTabs` の `compact`（スマホ `h-9`、PC `h-10`）を使う。
  - 操作ボタン: スマホは `h-8` まで。見出しの横に添えるボタン（説明・詳細）は `h-6` 前後（`DetailButton compact`、`StatusLegendDialog compact`）。
- 文言の長いボタンは短くし、正式な操作名は `aria-label` に持たせる（例: 表示は「比較」、aria-label は「比較に追加」）。
- 2つの要素が狭い幅でも収まるなら横に並べる（例: コースとリフトの集計は `grid-cols-2`）。1列あたり約170px（375px幅の端末）に収まるように文字と記号の大きさを決める。
- 余白（`py-*`/`gap-*`/`mt-*`）は小さめから始める。広げるのは読みにくいと分かってから。ただし詰めすぎて読みにくくするのも駄目。文字サイズの強弱（大事な値は大きく太く、補足は `text-xs` で薄く）で密度を上げる。
- ボタン・チップ・バッジの文字は絶対に折り返さない（`whitespace-nowrap`）。「詳\n細」のように縦に割れたら列幅か配置が間違っている。表の中のボタン列は、ボタンが1行で収まる幅を確保する。
- スキー場詳細の天気タブ「リンク一覧」は、4サイト（Snow Forecast・tenki.jp・ウェザーニュース・Windy）のリンクがそれぞれ1件ずつの場合、スマホでも必ず横1列に全て収める。各1件の4リンクを2行にしたり、横スクロールで済ませたりしない。同じサイトに複数地点などの項目がある場合は2行以上に折り返してよい（リンク内の文字は改行しない）。画面幅ではなくコンテナ幅に合わせて文字サイズと余白を調整し、320px・375pxのスマホと幅346px・500pxのPC詳細パネルで確認する。
- 「詳細」ボタンはどこでも `DetailButton` を使う。表の行や見出しの横では `compact`。独自の青いリンク文字などで代用しない。

## 2. 置かないもの

- ログイン／アカウントのボタンはホームの検索画面だけに置く。詳細・比較画面（PC・スマホとも）には表示しない。
- お気に入りはハートとピンク（pink-500）、比較は青に統一する。ホームの比較の入口は「♥お気に入りを比較」「N件を比較 ×」「比較リスト ›」を1行に並べる。丸い部品が多い画面なので、この3つは角の立った四角いチップ（`rounded-md`、太字、影付き）にして目立たせる。×で選択を消す前に確認する。「比較リスト ›」は保存したリストが1件以上あるときだけ出し、押すとリスト一覧のダイアログを開く。ホームのアカウント画像は直径32px、外枠なしで表示する。
- ホームの比較チップは固定幅を使わず、文字に合った幅にする。狭い一覧パネルでは左右の余白とチップ間の間隔を詰め、文字は12px、余裕がある場合は13pxにする。ブラウザ幅ではなく比較行のコンテナ幅で切り替え、3つのチップを1行に残す。検索結果の件数は比較の行に置かず、一覧の「名前順」の右に出す。
- 通常の比較画面の見出し行には、×の左に「リストに保存」（スマホは `ListPlus` アイコンのみ）を置く。既存リストへの追加か、新しいリストの作成を選べる。お気に入り比較ではヘッダーのハートと保存ボタンを出さず、概要カードの詳細の左にだけお気に入りのハートを置く。通常の比較と保存済みリストのカードにはハートを出さない。保存済みリストではヘッダーにスキー場追加ボタン（スマホはアイコンのみ）、概要カードに青い `ListMinus` の解除ボタンを置く。PCではリスト名を件数の左に出す。件数は読み込み中も比較対象の数を出す。最後のスキー場を外しても空のリストを保持し、追加できるようにする。
- 同じ情報や同じ操作を2か所に置かない。
- 値だけで意味が分かるものに「レベル」「圧雪」「営業状況」のようなラベルを付けない。値をチップにして横に並べる。
- 「日時不明」「コメントはありません」など、無いことを知らせるだけの文言は出さない。無ければ何も書かない（未取得を区別したいときだけ `NotFetchedBadge`）。
- 1画面に収まる量の情報をタブで分けない。重要度順に縦に並べる。

## 3. 情報の並べ方

- 見出し行に「名前・件数・説明(ⓘ)・詳細(›)」をまとめ、その下に中身、出典は最後に小さく添える（`SourceLine compact`）。
- 数字が主役のところは数字を大きく、記号（○△×）は数字より小さくする（`StatusMark size="sm"`）。
- 営業状況は一覧と同じ ○△× の記号＋「全面滑走可／一部滑走可／クローズ」の文言で書き、色付きの枠で一番目立たせる。
- 1行に横の余白が残るなら、出典や動画リンクなどの補足をその右に寄せて置き、行を増やさない。
- 別のスキー場名を並べるときは地図のラベルと同じ省略名（`getResortLabelName`）を使う。
- ホームの並び替えボタンとメニューは同じ文字サイズ・太さに揃える。「都道府県別」を選んだら、初期表示は地方だけにし、地方 → 都道府県 → スキー場の順に展開する。都道府県名の横の件数は、絞り込み後の検索結果だけを数える。
- 都道府県別の一覧は階層ごとに少し字下げし、地方名・都道府県名を太字で目立たせる。スクロール中は地方名（40px）と都道府県名（36px）を一覧の上端から2段で固定する。固定部分の上に余白を残さず、角丸部分も不透明な背景で覆って背後のカードを見せない。

### リンク集のタブ（スキー場のリンク一覧）

- グループと種類の並び順は全スキー場で同じにする（定義は `src/features/resort-links/linkTypes.json`）。リンクの無い種類・グループは出さず、順番だけを固定する。
- グループ名は小見出し（`text-sm` 太字）。その下に、種類名そのもののボタン（例:「コース営業状況」「リフト営業状況」「Googleマップ」）を横に並べて折り返す。押すとそのページを別タブで開く。「公式」「開く」だけのボタンを種類名の横に並べる形にしない。
- 同じ種類に公式のリンクが2〜3件あるときは、種類名に区別の名前か番号を添えたボタンにする（「レンタル料金（予約）」「ゲレンデマップ 2」）。1件のときの地点名・補足はボタンの `title` に持たせる。
- 外部サイト（ツアー会社など）が複数ある種類と、4件以上ある種類は、ボタンの下に「種類名（左・固定幅・`text-xs`）＋リンクのチップ（右・折り返し可）」の行でまとめる。公式は青のチップで区別の名前、外部サイトはグレーのチップでサイト名を先に書き、その後ろに区別の名前だけのチップを並べる。
- 1つの種類が8件を超えたら「ほかN件」でたたむ。チップの文字は折り返さず、長いものは省略（…）にする。
- サイト外へのリンクは必ず別タブで開く（`ExternalLinkComponent`。自前で書けない地図の著作権表示などはルートの `ExternalLinksInNewTab` が補う）。
- 天気のリンクは天気タブにもあるが、リンク集のタブは「全部のリンクが同じ場所にある」ことが目的なので重複を許す。
- SNSはリンク集の「SNS」グループに並べる（SNS専用のタブ・埋め込みは置かない）。X・Instagram・Facebook のボタンには `public/social` のロゴを種類名の前に添える。

### 雪マジ・EV充電のチップと、スキー場比較のリンク集

- 「雪マジ」「EV充電」は `ResortFeatureChips` を使う。詳細ヘッダーでは所在地のすぐ後ろ、比較の概要カードでは営業状況の右側に縦並びで置く。押せると分かるよう枠と「›」を付け、押すとモーダルで中身を出す。PCの詳細では、モーダルを詳細パネルの範囲の中だけに出し、地図の上に重ねない。
- 比較の概要カードはコース・リフトと出典だけを左側の枠に入れ、チップはその枠の外の右側に縦並びで配置する。営業状況の囲い・背景にチップまで含めない。カード幅は約350px（1440px前後の画面の4列・スマホ）を想定し、狭い幅でもコース・リフトの件数と出典を表示する。
- 比較の「リンク集」は、詳細のリンク集と同じ部品（`LinkGroups`／`LinkGroupBody`）と同じ並び順で出す。
  - スマホはゲレンデと同じ1画面1スキー場の横スワイプ（`CompareCarousel` の送りボタンと点）。スキー場名の行は残し、カードの中だけを縦に送る。
  - PCはグループ（基本・ゲレンデ・料金…）を行、スキー場を列にした表。スキー場名の行とグループ名の列を固定し、縦横ともタブの枠の中で送る。比較中のどこにもリンクが無いグループの行は出さず、リンクの無いマスは空のままにする。1列は20〜36rem。

## 4. 文字サイズの段階（スマホ → PC）

1か所だけ文字を小さく／大きくしない。同じ役割の文字は、同じ画面の中で必ず同じ段階を使う。ある部品を詰めたら、同じセクションの他の部品（表・コメント・出典・取得日時）も同じ段階に揃える。

| 役割 | スマホ | PC（`md:`） | 例 |
| --- | --- | --- | --- |
| セクション見出し | `text-base` | `text-base` | 営業状況、ゲレンデマップ |
| 小見出し | `text-sm` | `text-sm` | コース、リフト、コンディション、コメント |
| 主役の数字 | `text-base` 太字 | `text-base` 太字 | ○△× の件数 |
| 値・本文 | `text-sm` | `text-sm` | コンディション表のセル、コメント本文 |
| 補足 | `text-xs`（11〜12px） | `text-xs`（12px） | 表の列見出し、件数の単位、出典、取得日時、`NotFetchedBadge` |
| タブ | `text-[13px]` | `text-sm` | ゲレンデ／料金／天気／リンク集／投稿 |
| スキー場名（詳細ヘッダー） | `text-lg` | `text-lg` | 詳細の先頭 |
| スキー場名（一覧カード） | `text-base` | `text-base` | ホーム一覧。ふりがなは出さず、詳細だけに出す |

- PC でもスマホと同じ段階を使い、`md:` で文字を大きくしない。PC は文字を大きくするより、地図を広く取り、一覧で多くの件数を見せる。テスラ車載ブラウザ（幅約1000px）でも同じ。
- 詳細パネルと一覧パネルはPCで約360pxまで縮む。狭い側はスマホと同じ密度で収め、文字は上の段階から下げない。
- 一覧カードの値（コース・リフト・料金）は、値があるときだけ青で目立たせ、「不明」を含む値はグレーの細字にする。
- `SourceLine compact`・`StatusLegendDialog compact`・`StatusMark size="sm"` は、スマホだけ小さくなり PC では通常の大きさに戻る。
- 変えたら、スマホ（375px）と PC の両方で実際の `font-size` を測って、上の表とずれていないか確かめる。

## 5. PC の詳細パネル

- 右パネルの幅は `--desktop-detail-panel-width`（`src/app/globals.css`）= `clamp(360px, 36vw, 480px)`、一覧パネルは `--desktop-search-panel-width` = `clamp(360px, 34vw, 440px)`。地図を画面の6割以上に保つための幅。
- 料金タブの公式リフト料金表（5列）は幅450px以上で横スクロールなしに収まる。それより狭いパネルでは表の横スクロールで全列を読めるようにする。幅を変えたら、一覧カードの「料金 営業期間外」が切れないことと料金表を確認する。
- パネルの中身は基本的にスマホ幅で組んだものを使う。PC だからといってこれ以上幅を広げない。
- 詳細の5タブ（ゲレンデ／料金／天気／リンク集／投稿）は `UnderlineTabs` の `fit` で均等に収め、横スクロールの先に隠さない。タブ高さはスマホ36px・PC40pxを維持する。幅320pxでは「ゲレンデ」が枠いっぱいになるので、これ以上タブを足すときは名前を短くする。
- 料金表の列余白は `price-table` コンテナで決める。ルスツの5列は詳細幅450pxでも収まる。それより狭い場合は文字を過度に縮小せず、表の横スクロールで全列を読めるようにする。

## 6. 高さを変えたときの連動箇所

- `UnderlineTabs` の高さを変えたら、その下に貼り付く sticky の `top-*`（例: `src/features/resort-detail/tabs/OverviewTab.tsx` の「戻る」帯）も合わせる。
- モバイル検索ヘッダーの高さは `MOBILE_SEARCH_TOP_BAR_HEIGHT` を共有する。地図はヘッダーの背後まで描画し、初期位置・検索結果の表示位置では `data-map-top-controls` の高さを避ける。リストだけはヘッダーと、比較チップの行（36px。チップが1つも無いときは行ごと出さない）の高さを上の余白に取る。日程・人数の条件と並び替え・件数はその下に4pxの間隔で並べ、件数は並び替えの右に置く。

## 6. コース・リフトの詳細と地図

- スマホのコース詳細は、地図と両方の内容が同時に収まらないため「断面図／斜度の近いコース」のタブで切り替える。名前・営業状況・数値は共通で残し、初期表示とコース選択変更後は断面図を開く。タブは高さ36pxでスクロール中も残し、斜度の近いコースは取得できた表示件数を添える。コメント・紹介・メディアはタブ内容の下に置く。斜度の近いコースの表示条件を満たさない場合はタブを出さず、PCは従来の縦並びとする。
- 名前の横にレベル・圧雪（リフトは種別・速度）のチップを並べる。長い名前は折り返し、チップは名前に続ける。最長クラス（例: かぐら「X4 かぐら第1高速リフト～田代第1高速リフト連絡」）でスマホ幅を確認する。
- 閉じる（×）ボタンはスマホ `size-7`、PC `size-8`。
- 何かを選択したとき、ほかのコース・リフトは「沈めるが消さない」。コースは形が読める濃さの灰色＋白縁で残す（`finalizedLayers.ts` の `DIMMED_STYLE`）。コースを選んでいるときのリフトは沈めず、ふだんどおり色と流れる動きで出す。リフトを選んだときのほかのリフトは紺で沈めるが、流れは止めない。
- コース比較の地図は斜度モードで、スキー場全体のコース・リフトを出し、比較するコースに寄せた状態から始める。ほかの名前は選択中の線に重ならない位置にだけ薄く出す（`showContextLabels`）。
- コース比較の地図は `embedded`：現在地は出さず、表示位置も保存しない（前の比較の位置を引き継がない）。拡大・縮小と方位のボタンは小さい版を使い、寄せる動きは出さない。評価基準などのタブを切り替えても地図をアンマウントしない（`keepMounted`）。読み込み中の枠は地図と同じ高さにして、表示が跳ねないようにする。
- PCのコース比較は、上の段に2コースの名前と地図を左右半分ずつの幅で並べ、下の段に「左の断面図｜数値の縦の表（左の値｜項目｜右の値）｜右の断面図」を置く。MacBook の画面でスクロールせずに収まる大きさにする（地図 `md:h-64`、断面図は `maxPlotHeight` で高さを抑える）。名前は横1行に収まるよう小さめ（スキー場名 `text-xs`、コース名 `text-[13px] md:text-sm`）。PCは断面図をなぞると同じコースの地図に点と斜度・標高を出し、断面図の上の読み値（斜度・標高・水平距離）は出さない。スマホはタブを「地図／断面図／評価基準」の3つにし、2コースを縦に積む。スマホでは比較表を出さず、断面図タブでいつもの横並びの数値（`FeatureMetrics`）を各断面図の上に出す。「選択中」「斜度の近いコース」のような区別のラベルは付けない。
