# UI 指針（スキー場詳細・スマホを中心に）

画面を作る・直すときに守ること。迷ったら「スマホで地図と中身がどれだけ見えるか」を優先する。

## 1. スマホは縦の余白を最優先で守る

- 縦の場所を取る要素は、毎回「これは本当に1段必要か」を確認する。ボタンは見出しや名前と同じ行に並べ、ボタンだけの行を作らない。
- ヘッダー・タブ・ツールバーの高さの目安:
  - 詳細ヘッダー（名前＋所在地＋操作ボタン）: ボタンは1行に横並び。2段に積まない。
  - タブ（`ゲレンデ`/`SNS`/`料金`/`天気` など）: `UnderlineTabs` の `compact`（スマホ `h-9`、PC `h-10`）を使う。
  - 操作ボタン: スマホは `h-8` まで。見出しの横に添えるボタン（説明・詳細）は `h-6` 前後（`DetailButton compact`、`StatusLegendDialog compact`）。
- 文言の長いボタンは短くし、正式な操作名は `aria-label` に持たせる（例: 表示は「比較」、aria-label は「比較に追加」）。
- 2つの要素が狭い幅でも収まるなら横に並べる（例: コースとリフトの集計は `grid-cols-2`）。1列あたり約170px（375px幅の端末）に収まるように文字と記号の大きさを決める。
- 余白（`py-*`/`gap-*`/`mt-*`）は小さめから始める。広げるのは読みにくいと分かってから。ただし詰めすぎて読みにくくするのも駄目。文字サイズの強弱（大事な値は大きく太く、補足は `text-xs` で薄く）で密度を上げる。
- ボタン・チップ・バッジの文字は絶対に折り返さない（`whitespace-nowrap`）。「詳\n細」のように縦に割れたら列幅か配置が間違っている。表の中のボタン列は、ボタンが1行で収まる幅を確保する。
- 「詳細」ボタンはどこでも `DetailButton` を使う。表の行や見出しの横では `compact`。独自の青いリンク文字などで代用しない。

## 2. 置かないもの

- スキー場詳細（PC・スマホとも）にはログイン／アカウントのボタンを置かない。ログインは検索画面のヘッダーだけ。
- 同じ情報や同じ操作を2か所に置かない。
- 値だけで意味が分かるものに「レベル」「圧雪」「営業状況」のようなラベルを付けない。値をチップにして横に並べる。
- 「日時不明」「コメントはありません」など、無いことを知らせるだけの文言は出さない。無ければ何も書かない（未取得を区別したいときだけ `NotFetchedBadge`）。
- 1画面に収まる量の情報をタブで分けない。重要度順に縦に並べる。

## 3. 情報の並べ方

- 見出し行に「名前・件数・説明(ⓘ)・詳細(›)」をまとめ、その下に中身、出典は最後に小さく添える（`SourceLine compact`）。
- 数字が主役のところは数字を大きく、記号（○△×）は数字より小さくする（`StatusMark size="sm"`）。
- 営業状況は一覧と同じ ○△× の記号＋「全面滑走可／一部滑走可／クローズ」の文言で書き、色付きの枠で一番目立たせる。
- 1行に横の余白が残るなら、出典や動画リンクなどの補足をその右に寄せて置き、行を増やさない。
- 別のスキー場名を並べるときは地図のラベルと同じ省略名（`getResortLabelName`）を使う。

## 4. 文字サイズの段階（スマホ → PC）

1か所だけ文字を小さく／大きくしない。同じ役割の文字は、同じ画面の中で必ず同じ段階を使う。ある部品を詰めたら、同じセクションの他の部品（表・コメント・出典・取得日時）も同じ段階に揃える。

| 役割 | スマホ | PC（`md:`） | 例 |
| --- | --- | --- | --- |
| セクション見出し | `text-base` | `text-lg` | 営業状況、ゲレンデマップ |
| 小見出し | `text-sm` | `text-base` | コース、リフト、コンディション、コメント |
| 主役の数字 | `text-base` 太字 | `text-lg` 太字 | ○△× の件数 |
| 値・本文 | `text-sm` | `text-base` | コンディション表のセル、コメント本文 |
| 補足 | `text-xs`（11〜12px） | `text-sm` | 表の列見出し、件数の単位、出典、取得日時、`NotFetchedBadge` |
| タブ | `text-[13px]` | `text-base` | ゲレンデ／SNS／料金／天気 |

- スマホで縮めた部品は、PC では `md:` で1段上げる。PC はパネル幅に余裕があるので、スマホ用の小ささのまま残さない。
- `SourceLine compact`・`StatusLegendDialog compact`・`StatusMark size="sm"` は、スマホだけ小さくなり PC では通常の大きさに戻る。
- 変えたら、スマホ（375px）と PC の両方で実際の `font-size` を測って、上の表とずれていないか確かめる。

## 5. PC の詳細パネル

- 右パネルの幅は `--desktop-detail-panel-width`（`src/app/globals.css`）= `min(500px, 45vw)`。地図をなるべく広く見せつつ、料金タブの公式リフト料金表（5列）が横スクロールなしで収まる幅。
- 幅を変えるときは、一番幅を使う料金タブの表が収まるかを必ず確認する（400px では小人以降の列が切れる）。
- パネルの中身は基本的にスマホ幅で組んだものを使う。PC だからといってこれ以上幅を広げない。

## 6. 高さを変えたときの連動箇所

- `UnderlineTabs` の高さを変えたら、その下に貼り付く sticky の `top-*`（例: `src/features/resort-detail/tabs/OverviewTab.tsx` の「戻る」帯）も合わせる。
- モバイル検索ヘッダーの高さは `HomeLayout.tsx` の `pt-[calc(...+4.6875rem)]` と同期している。

## 6. コース・リフトの詳細と地図

- 名前の横にレベル・圧雪（リフトは種別・速度）のチップを並べる。長い名前は折り返し、チップは名前に続ける。最長クラス（例: かぐら「X4 かぐら第1高速リフト～田代第1高速リフト連絡」）でスマホ幅を確認する。
- 閉じる（×）ボタンはスマホ `size-7`、PC `size-8`。
- 何かを選択したとき、ほかのコース・リフトは「沈めるが消さない」。コースは形が読める濃さの灰色＋白縁、リフトは位置の目印になる紺の実線で残す（`finalizedLayers.ts` の `DIMMED_STYLE`）。
- コース比較の地図は斜度モードで、スキー場全体のコース・リフトを出し、比較するコースに寄せた状態から始める。ほかの名前は選択中の線に重ならない位置にだけ薄く出す（`showContextLabels`）。
- 比較の地図は縦に積み、PCは各地図の横に断面図を置く（タブで分けない）。スマホは地図／断面図を切り替える。
